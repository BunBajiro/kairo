# Draw coverage audit

The first complete boundary-timer diagnostic (`browser/result.json`) successfully covered native pan/zoom, both projections, near-overview and closer views, and populated activity backgrounds. Its raw `frames[].labels` is **zero throughout**: the wheel sequence reached scale 4.32 at most and then zoomed back out. Therefore its generic check text mentioning “label-scale zoom” is not supported for **system labels**. The actual region/territory label paths did execute. Do not treat this first run as evidence about dense system-label collision/sorting.

A separate `draw-browser-labels.mjs` supplement uses seven wheel steps and explicitly requires nonzero system-label candidates in each projection/background before accepting its run. Its results use a new `labels/` directory. The initial run remains unchanged so the coverage correction is auditable.

The only application differences in the diagnostic checkout are boundary clocks, a gate-draw counter and a returned per-frame diagnostic record. No rendering predicate, visible point order, gate order, collision rule, source update or frame scheduling is changed. The instrumentation patch is generated by `instrument-draw.py`, whose SHA is pinned in every diagnostic result. These timings are attribution under instrumentation, not claims about unmodified frame speed or an A/B optimization.
