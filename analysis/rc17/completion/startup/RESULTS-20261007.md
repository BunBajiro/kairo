# Startup index ablation — completed 7 October 2026

This is the reconstructed, now executed two-file experiment. It compares frozen fa6 and canonical RC16 with an isolated fa6 checkout containing only the a27 market-taxonomy and Intel-prefix changes. It does **not** measure the later combined completion source or close G6 by itself. No lost October 3 result is reused.

[Raw completed record](abba-20261007/startup-abba-completed.json) contains all 99 fresh-process children, exact source/build/harness identities, output equality checks and before/after source verification. The runtime slot was exclusive. Ordinary timing uses three ABBA cycles per comparison; collected heap and logical counters are separate lanes. Cold means a fresh JavaScript process, with normal filesystem caching.

## Ownership and retained heap

Logical instrumentation confirms the two default taxonomy consumers share one index. Their acquisition allocates zero Maps; first use creates the four index Maps and one request-local result Map. The previous factories each created four index Maps. Intel abbreviation storage changes from 19,066 prefix keys / 29,023 candidate references to 4,087 bucket keys / 8,446 references; exact-name and ambiguity outputs match.

Separate collected-heap samples show Core heap after construction at 40.749 MiB (fa6) versus 32.811 MiB (variant), and after first Market use at 40.900 versus 35.891 MiB. The process-scoped taxonomy index deliberately survives consumer release: standalone after-release heap is 9.709 MiB versus 8.129 MiB for fa6. This is ownership shifted to one process cache, not zero retained cost. In the real Core case the two consumers coexist; after-close Core heap is 28.704 versus 30.271 MiB. Heap/RSS capacity and long-lived process behavior are not inferred from these short forced-GC observations.
