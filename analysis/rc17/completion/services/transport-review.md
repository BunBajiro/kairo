# Independent shared public feed transport review

Review date: 7 October 2026. Read-only review of the reconstructed working tree by the Auth/services reviewer. No runtime tests were executed for this review during the source freeze. The unpublished 3 October review and raw runs are not acceptance evidence for this source.

**Finding:** a late review found that counting only the flight map allowed repeated cancellation/replacement of a queued URL to retain more task closures than `maxPending`. The author corrected admission to count all accepted tasks until their `finally` handlers finish, and close now awaits that complete task set. This reviewer re-read the correction and its blocked-head/same-key regression. No remaining blocker was identified for the current Core wiring; execution of the amended test belongs to the author/root gate. This is a source/contract review, not a claim of real-provider latency or throughput improvement. The controlled request-count fixture is recorded separately in `before-20261007.json` and `after-20261007.json`; it reduces the overlapping fixture's six requests to four while preserving two independent missing-head 404 requests.

| Contract | Review result and test coverage inspected |
| --- | --- |
| Scope and privacy | `wrap` shares only the fixed R2Z2 pointer or numeric packet GET URLs. Body-bearing calls, explicit included credentials, Authorization/Cookie headers and unrelated providers use the original fetcher. Provider state is keyed by the underlying fetcher identity. Header differences remain in the flight key except User-Agent/compression negotiation; neither response objects nor private consumer state are shared. The identity/provider/credential test exercises these boundaries. |
| Response semantics | Each subscriber receives a new Response with its own decoded byte copy, status, status text and headers. Content-Encoding is retained without decoding bytes again. Non-success bodies are released because both existing consumers inspect status before body; status and Retry-After remain available. Failure statuses and transport errors never enter the reuse cache. Tests cover independent reads/header mutation, compression headers, 404/429/503 and recovery. |
| Body limits | Universe keeps its 2 MiB actual-body and Content-Length checks; Session retains its 4 MiB actual-body check. Streaming rejects only subscribers whose limits are exceeded, allowing a larger subscriber to finish. Cache reuse repeats the receiving subscriber's limit check. All streamed collection is bounded by the largest accepted subscriber limit, at most 4 MiB; interrupted or oversized readers are cancelled. Tests cover different limits, misleading length, cached large bodies, oversized recovery and body cancellation. |
| Deadlines and cancellation | Consumers retain their 12/15-second signals including queue wait. The shared upstream gets a separate 15-second bound after dispatch. One departure removes only that subscriber; the last departure aborts the entry controller. A queued abandoned entry checks abort before network dispatch. Tests cover independent timeout, all-leaver abort, queued cancellation and disabling either real consumer while the other completes. |
| Pointer rollover and bounded reuse | Pointer responses share only an active flight. A successful pointer clears that fetcher's packet reuse cache; no pointer or failure response is retained. Successful packet reuse expires at 30 seconds on access and is bounded to 32 entries/8 MiB per fetcher. Lazy expiry is not a promise to physically free idle bytes at the deadline. Tests cover exact expiry, entry/byte eviction, successive pointers and changed packet bytes. |
| Provider budget and lifecycle | At most 16 accepted tasks remain pending per fetcher, including cancelled/replaced entries until their tasks finish. Joins to an existing live flight do not consume another task. A serial task chain includes body collection and a 110 ms dispatch floor. Cached responses consume no budget. Core closes both consumers before the owner; owner close rejects pending subscribers, aborts queued/active entries, awaits tasks and clears retained state. Tests cover aggregate dispatch spacing, capacity, repeated same-key cancellation behind a blocked request, close identity/drain and no new admission. Unrelated forwarded calls retain their consumer's lifetime ownership. |
| Consumer acknowledgement | Raw sharing does not merge Session verification/acknowledgement with Universe normalization/cursor advancement, force/backoff rules or enable state. Tests inspect independent cursor progress after failed verification, later retry beyond cache age and one-sided disable. The real Core test verifies the shared packet through ESI before personal and alliance ledger persistence; the callback-only count fixture is not a substitute for this contract. |

The transport-specific test file contains 13 top-level cases and two nested disable cases. Its current execution result belongs to the Session owner's fresh verification and the root's combined gate; this review does not add another passing-test count. Serial body collection may change individual queue wait, so request savings alone do not establish an elapsed-time benefit.
