## Failure and cleanup records

An existing output directory is rejected before modifying it. Once the new output directory exists, the runner writes an initial receipt before parsing configuration or reading sources. If even that directory cannot be created, only stderr can be retained by the caller. Each child has exclusive stdout/stderr logs, result output, and an owned `TMPDIR`. Logs are hashed after the process and pipes close. On timeout or interruption, the runner signals the process group TERM, escalates to KILL after the recorded grace, and waits for actual child close before asserting failure or touching its temporary data.

After leader close, the runner separately probes the process group and `/proc` member states, terminates any live survivor, and waits for actual disposal. A worker that leaves descendants is a failed worker even when forced cleanup succeeds. If live descendants remain after TERM/KILL grace periods, a visible `cleanupBlocked` receipt is updated while locks and temporary data are retained; final logs are not hashed and no following worker starts. Zombie/dead-only (`Z`/`X`) members cannot execute/write, so they allow a failed cleanup receipt to finish without waiting indefinitely for external init to reap them. Signal handlers stay active through draining/log closure and outer finalization so another stop does not bypass cleanup. Temporary removal and provenance checks remain independent after live-group disposal. Unchanged historical workers may not produce their own failure receipt; the enclosing receipt preserves their actual exit/signal, stdout/stderr, residual temporary directory names, output artifacts and independent cleanup/source outcomes. It never treats a timed-out, nonzero, signaled, unclosed, incomplete or mismatched child as passing. The attempt fails at its first unsuccessful child; it is not silently rerun or resumed. Start a new attempt after a reviewed correction, preserving the failed attempt.

This envelope does not execute the separate final current-source browser/names/M6/F6 gates, loaded updater, package extraction, Auth/lifecycle suite or independent CI. Follow the runbook for those gates and evidence banking.
