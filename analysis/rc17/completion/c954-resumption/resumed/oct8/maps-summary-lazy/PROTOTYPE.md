The helper uses private SQL AUTOINCREMENT generations, returned as text, to guard publication. Triggers only invalidate; no SQL JSON functions run on map writes. Existing maps acquire dirty key entries lazily for the requested pilot. A miss uses JavaScript's existing parse, preserves unsupported full fallback, and derives only descriptor/cleanup fields. Connection notes and arbitrary extra fields never enter supported compact connection objects. Ready/fallback formats are version checked on every read; unchanged ready/fallback reads do not write.

Static authoring found and corrected a lazy-specific identity trap: cleanup may mutate a parsed object and persist by its document ID even when its SQL row key differs. That does not necessarily invalidate the original row's generation. The compact snapshot is therefore built **before** reconciliation from the exact parsed row, and conditionally published afterward using its original SQL key/generation. Cleanup changes at the same key invalidate publication; cleanup at another key leaves metadata describing the unchanged original row. New cold and warm key-move tests explicitly cover this and surviving arbitrary fields.

Focused tests cover no startup body backfill, first/steady/reopen behavior, direct DML/replacement/owner/key/kind collisions, two-handle stale publication and delete/reinsert ABA, generations beyond 2^53, parent/savepoint rollback, format mismatch, missing-trigger repair, installer/invalidation failure, publication lock contention, primitive/duplicate-key/locked-own semantics, source falsy recreation, pruning/expiry and existing scoped-read behavior. `git diff --check` passes.
