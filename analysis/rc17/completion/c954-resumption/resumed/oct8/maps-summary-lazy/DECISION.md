# M9: close the conditional strategy by measured retention

**Root decision, 8 October 2026: reject the lazy persisted-summary prototype as-is for this RC17.** Retain the accepted 9afa response-local roster work and no-op reconciliation, together with the current canonical-body summary reads. Application candidate remains `70cd12f`; this isolated prototype has not been integrated. No further M9 experiment is scheduled this pass absent new evidence from the final source.

The prescribed first screen completed all eight shapes in four fresh ABBA arms, with exact output/authoritative parity, no steady-state writes, successful source/harness guards and verified raw logs. Independent review checked all 624 numeric comparisons. The rejection is a performance and ownership tradeoff decision, not a correctness failure in the covered cases.

The rejected prototype reduced wide-24 steady summaries from about 270–278 ms to 22–25 ms (91–92%), and real node response+summary+detail cycles from 372–388 ms to 147–151 ms (about 61%). Its narrower metadata also avoided the eager design's arbitrary-note duplication: dense-eight checkpointed DB overhead was 3.73%, not the earlier separate eager trial's 75.3%.

Those wins do not establish the representative foreground/background tradeoff. Wide-24 node responses alone rose from 55–60 ms to 71–82 ms, selected node detail from 16–17 ms to 23–27 ms, and comment detail from 20–23 ms to 26–34 ms, in both pairs. Canonical expiry was slower in both pairs for seven of eight shapes; dense-eight rose from 193–199 ms to 279–287 ms. Small cases were mixed, first misses have publication costs, unsupported fallback adds overhead, and the change introduces durable derivative schema, invalidation, versioning and storage ownership. Five steady observations in the fixture are not an application's read frequency.

**The retained implementation's wide-24 steady summary cost remains about 270–278 ms on this fixture, with whole-body parsing still present. It is not fixed or claimed implemented by this decision.** The M9 conditional optimisation strategy is closed by measured retention, while this explicit performance limitation remains visible in the RC17 handoff. The rejected SQL-on-read and eager persisted trials, this lazy trial's wins and adverse results, and the eager log-integrity qualification all remain in the evidence record.

The lazy candidate's background-tracking-after-warm-publication coverage and adverse-case causal explanation remain unproven. They were adoption-only gates; they are unnecessary for this rejection and are not pending RC17 tests for an unshipped implementation. Real node/comment edits, undo and simple native import/removal were exercised in this screen, but no broader lifecycle or performance closure is implied. No trigger, metadata table, retained JavaScript cache or migration from this prototype is added to the application.

Evidence: `RESULTS-SCREEN.md`, `INDEPENDENT-RAW-REVIEW.md`, `screen-attempt1/completed.json`, the four raw arm JSON files, `screen-attempt1/summary.json`, and the exact source/patch/harness manifests. `SCREEN-BANK-INVENTORY.json` pins the completed local bank. The root owns GitHub publication and final combined-source release gates; this decision does not reopen withdrawn PR #10 or produce a clean RC17 by itself.
