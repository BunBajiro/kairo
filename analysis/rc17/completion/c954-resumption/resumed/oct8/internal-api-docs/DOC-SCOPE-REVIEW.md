# Independent documentation scope review

Read-only review against accepted application a7b1bf9 and the new internal-API draft. No application documentation has been edited or removed by this reviewer. The existing README plus 23 Markdown files in `docs/` total 2,299 lines; much of the avoidable repetition is historical release evidence mixed into current entry points, not the useful domain guidance.

## New architecture guide review

`INTERNAL-API-DRAFT.md` accurately follows the current source owners. The Core facade names/signatures, `api` example, `useResourceRefresh` signature, semantic-versus-invalidation distinction, bus promise ownership and Session edit flow match the source inspected. The example's Session IDs are current generated UUIDs; the generic Session dispatcher still extracts a raw segment, unlike the explicitly decoded replay route. The HTTP reference records that distinction.

The draft correctly keeps the proposed separate names event out of the deployed contract. Its explanation of complete snapshot metadata, global owner 0 versus selected-pilot ownership, one active read plus one follow-up, and process-qualified opaque tokens is useful for both human and AI developers. Retain those specific contracts. No code-signature blocker found.

Avoid preserving the same lifecycle, extension and endpoint prose twice: make this guide the primary feature-development workflow, API-REFERENCE the dispatcher/event contract, and ARCHITECTURE a compact source-owner map and architecture entry point. The legacy architecture module example remains a useful runnable reference; move it into the new guide or link to one maintained example rather than keeping separate copies.
