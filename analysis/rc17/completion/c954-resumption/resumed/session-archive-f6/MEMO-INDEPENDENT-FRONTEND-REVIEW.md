8 October 2026. Read-only source and saved-evidence review; no application, build, test or browser runtime. The narrow card memo is supported for adoption, with the final merged wiring gate still required.

I rehashed all six ordinary worker results and both originating completion receipts. All 486 checks pass, with source verification, cleanup promise completion, no recorded errors/external traffic, and identical paired fixture/durable-data hashes. Card presentation hashes, complete card counts, archive element counts and archive heights match in all three pairs at 30/300/1,500 cards. I independently recomputed all 68 scalar summary metrics, including each paired ratio and separate first/second report openings. `MEMO-INDEPENDENT-NUMERIC-REVIEW.json` preserves those calculations (SHA `4a1bef543215d1c7573df17d389e4bd7c62a7fab93624cf3092cece1c758d43d`).

The single source delta uses React's normal shallow memo comparison over every consumed card input: ID, label, start timestamp, calculated whole minutes, active state and callback. Minutes are still calculated by the parent on each render; the callback changes with the current character and retains the actual clicked button for focus restoration. No revision-only comparator, stale session-object shortcut, ordering change or DOM removal is introduced. The candidate intelligence file is `4c3f21fed3d50a453c58df6b6f448ba93e7d2d6942f5bc6b1ad397d3eb797dd4`; the patch is `719fc58da60cca22399f35f9dd44f91dc03dca69c6cfdb5ccab71b599a8aa464`, applied after the common focus patch.

Refresh task medians fall from 18.163 to 12.814 ms, 97.610 to 72.581 ms, and 503.117 to 403.122 ms at the three prefixes. Each individual pair improves. The 1,500-card refresh script medians fall from 140.840 to 12.109 ms. These are renderer observations for this fixture, not application-wide CPU claims.

Adverse observations remain relevant: 30-card first report opening increases by 13.225 ms (+20.53%) in pair 2 and 7.457 ms (+9.67%) in pair 3; 300-card second opening increases by 25.794 ms (+17.77%) in pair 3; 1,500-card scroll task increases by 19.992 ms (+1.64%) in pair 1. Initial navigation is 1.4 ms slower in pair 3, with the initial cumulative TaskDuration counter 19.833 ms higher; that counter is not a separately bounded navigation work window. No numeric regression threshold was declared for this lane, and none is introduced retrospectively.

Keeping all loaded cards preserves the existing DOM/search/reachability contract but does not solve its scaling cost: 1,500 cards still have 22,500 archive elements and roughly 1.24 seconds of measured scroll task work. Native browser Find remains a runtime capability limitation, not accepted coverage. The forced-GC retention samples do not establish leak freedom. Historical cleanup flags establish successful close promises, not independent actual Chromium exit; the final merged harness uses the reviewed strict helper.
