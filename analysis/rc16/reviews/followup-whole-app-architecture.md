# Whole-application architecture review

This review explicitly includes inherited Kairo systems as well as the 8.0 sprint. It is a structural source review with exact RC16 references; measured/reproduced findings are identified separately. It supplements [architecture.md](architecture.md), [followup-restart.md](followup-restart.md), the independent service review and feature reviews. No production source changed during this review.

## Cross-feature pressure already established

The initial audit identified no-op Combat UPSERTs feeding Universe politics triggers, work performed before the live-session two-minute deadline, full binding projection plus unconditional Stream state broadcasts, and unbounded durable job/cache/evidence histories. These are inherited/new-feature interactions rather than evidence that every service needs replacement. Maps follow-up measured repeated all-pilot reads and signature lookups; request-scoped access and explicit mutation/reconciliation ownership address those costs more directly than a schema-wide or service-wide rewrite.

The historical v0.7.3 improvements remain present in import-cache, market history storage, market/archive logic, session combat and projections. Preserve cache-first reads, cancellation/progress boundaries, existing public collection cadence, index coverage, stale-source labels and explicit command non-replay. The broadened scope does not justify undoing these protections.

## Refactoring boundaries

Keep service APIs explicit and close to their owners. Core legitimately coordinates character polling, protection and feature lifecycle; file length alone is not a reason to split it. The useful backbone is a small admission/drain/close contract and shared data access where repeated work is evidenced. Avoid a global scheduler, universal repository/ORM, generic caching layer, or one shared retry policy that erases the deliberate differences between replay-safe reads and external commands.

All performance figures should be taken from the linked measured reports and raw manifests. This review adds structural coverage and implementation boundaries, not new timing claims.
