## Concrete quality/edge-case lessons

1. `IntelCache[0]` is unguarded and only one list item is evaluated for warnings after list synchronization. Confirm manager dispatch guarantees before calling an empty-update crash a confirmed defect; architecture should evaluate semantic new events, not current UI first row. Multiple reports need dedup/cooldown/coalescing, clear-event handling and source timestamps.
2. Unknown-message warning sets both sound and flash before global switches, and explicit-alert filter uses raw case-sensitive substring matching. Kairo should expose predictable rule precedence with preview/test and independent channels.
3. Empty or malformed nonempty signature paste yields zero accepted rows and marks every existing signature missing. It does not delete automatically, but selecting all for Delete is risky. Validate/preview parsed count before proposing missing signatures; mark observation source/time/system; never move data to a pilot's newly changed location silently.
4. A known signature type is never corrected by later known-type paste. Kairo should merge intentionally and allow correction. Parser localization should not silently fail when the UI itself supports Chinese.
5. Fleet double-click is wired to local-character handler but roster objects are `FleetMember`, not `LocalCharacter`, so the cast fails and no navigation occurs. Use typed selection callbacks and per-row interaction tests.
6. Main-window character deletion lacks the character-window confirmation; all-character context clears even when deleting a different pilot. Kairo should keep source/active-pilot boundaries explicit and use undo/consistent destructive controls.
7. The data-menu log cleanup deletes files in fixed default paths, ignores configured watcher folder, uses creation age, swallows failures, and has no confirmation in the handler. Never copy this as routine maintenance. App-owned retention is separate from deleting EVE's source logs.
8. Intel double-click opens arbitrary detected links and navigates in the same gesture. Kairo should separate inspect-on-map from clearly labeled external-link actions.
9. Fonts can be 7px secondary /10px kill rows /8px intel preference minimum. Keep Kairo 16px primary/14px supporting text and stronger contrast, progressive detail.
10. UI says changing log folders needs restart, while handlers immediately reload watchers. Derive notices from actual lifecycle; show watcher state and parse diagnostics.
11. Public zKill filter clones and filters the stream for every candidate row to take30; replace with memoized bounded selectors. Hover loops over every intel UI item; index by system ID. Avoid one-second whole UI refreshes for static views.
12. Primary + backup layout loading, atomic save and status/error surface are good resilience patterns. Kairo's SQLite and explicit source states are a stronger foundation than saving signatures only on orderly close.
13. Settings overlap (beacons duplicated) and `ZkillExpireTimeMinutes` setter changes the unrelated `UpcomingSovMinutes` when below minimum (`MapConfig.cs:1222`). Typed validation and one owner per setting avoid drift.
14. Hard-coded capital range presets, name-parsed bridge discovery and special-network shortcuts need provenance/version/capability labels; range feasibility never proves docking, cyno, fuel or access.
15. On-map/current-region filtering must not alter geopolitical denominators or evidence. Kairo already has full-roster analysis independent from view and conservative configured/inferred provenance.

## Kairo comparison

Kairo already exceeds these UI workflows in evidence-aware political grouping, configured manual precedence, honest independent/unassigned membership, source availability/freshness, unknown rather than zero activity, replay historical/live separation, unified system/region/territory keyboard search, responsive readable default map workspace, bounded K/J-space, persistent discovered wormholes, access-aware private links, route exclusions, and OPSEC-aware stream output. Preserve those constraints.

Kairo has route origin/destination, shortest/safer, hostile avoidance, enabled/access-confirmed Ansiblex and unexpired confirmed wormholes; physical jump range; editable pins/calendar context, imported CSV/TSV bridge lists; system structures/ADM/FW/incursions/industry/mining detail; existing session/combat history and stream toast engine. Universe lacks the above first-class ordered itineraries/alternate mids/export, tactical multi-range/radar, map-linked intel and warning policy, simultaneous pilot/fleet situational view, signature notebook, sovereign campaign/storm/POI/public connection event feed, custom infrastructure observations, exact SMT bridge-text parser and private tactical detached view.

Kairo stream rules are not a private operational alert inbox. Do not send local intel/fleet positions through OBS/public output by default. Reuse cooldown/event semantics but create a separate authenticated operational channel.

## Kairo-native information architecture

- Keep map as the default workspace. One compact command deck: scope (K/J + region), unified search, active pilot/follow, Layers, Operations. No fullscreen prerequisite.
- One operations dock with a readable tool selector instead of a growing row of permanent tabs: Inspect, Politics, Navigate, Intel, Explore. Contextual actions switch tools and preserve drafts, map camera and active scope.
- Inspect: selected-system overview, conditions, sovereign owner/bloc, local pilots/fleet, signatures/infrastructure context, route origin/destination/waypoint/avoid, watch scope. Overview remains region/full-space statistics when nothing selected.
- Politics: existing geopolitical atlas, sovereign share, member provenance, regional holdings, actual gate frontiers; relevant campaign/timer events attach to selected territory. Reported ownership remains separate from inferred affiliation.
- Navigate: Gate itinerary / Jump itinerary / Tactical range subtools. Reorder waypoints with arrows and drag, capability toggles, typed edge badges, risk/source briefing, alternate mids, fit route, copy text/EVE links and explicit Send waypoints. Mark partial routes and failed segments; clearing the planner does not silently clear EVE autopilot.
- Intel: chronological map-linked reports with scope (near pilot/route/current region/all), Fresh/Stale/History, clear/unknown distinctions; cached external kills/timers/storms/POI as selectable categories. Pilot/fleet list is a subview with source age, online and permission states. Watch briefing summarizes nearest fresh reports and active route exposure without claiming safety.
- Explore: signatures, special connections, saved observations/upgrades. Signature paste always previews accepted/rejected/missing rows in the explicitly selected system, preserves first-seen and last-seen, supports copy and reversible deletion. Private/third-party connections retain source/EOL/access boundaries.
- Settings Universe: Sources & ingestion, Watch & alerts, Pilots & fleet, Navigation defaults, Map/accessibility. Short current status + expandable advanced controls. Existing Power blocs remains separate named section in same settings tab. Source health and disabled/unavailable controls explain a real next action.
- Tactical detached window: explicit user gesture; authenticated page, readable scope/age and source badge, route/radar/alerts; Picture-in-Picture when supported and ordinary popup fallback. Preserve original map/camera and global app navigation. Do not call popup always-on-top if platform cannot provide it; don't put auth tokens/data in URL or public overlay.

## Recommended implementation order

1. Shared typed operation snapshot with source status, timestamps and stable IDs; safe ingestion/retention; native route result edge types.
2. Ordered itinerary and SMT bridge parser preview, copy/export, route briefing; first useful interactions on existing cached data.
3. Intel/pilot/fleet dock + read-only source feed cards; user-configured alerts default quiet with test/preview and cooldown.
4. Signatures/infrastructure notebook with paste diff and autosave; contextual map badges.
5. Tactical range/radar/schematic layout and detached private view. Add or expose controls only with real backing data/capabilities.
6. Full acceptance: zero clipboard matches, unknown names, expired/partial feeds, no pilot/no scopes, changed pilot during paste/send, blocked popup, permission denied, route partial failure, hidden dock keyboard focus, narrow screens, replay live-overlay suppression, reduced motion and no idle redraw.
