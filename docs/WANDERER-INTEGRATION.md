# Wanderer features in Kairo J-Space

This matrix compares Wanderer at **`6c5d43936e88f1d2acabc4d45fc82cbb67d4a08a`** with the pending **Kairo 0.8.0-rc.11** implementation. The [source audit](WANDERER-SOURCE-AUDIT.md) and [51-workflow baseline inventory](WANDERER-WORKFLOW-INVENTORY.md) record what was reviewed. This document describes implemented workflows and their material differences; it does not claim that Kairo is a hosted Wanderer replacement in every respect.

**Parity** means the core user task is implemented. **Parity + Kairo** identifies a supported task with a concrete additional capability or stronger data handling. **Adapted** means Kairo provides a local or differently presented equivalent. **Partial** identifies a remaining workflow difference. **Platform boundary** identifies a hosted/collaboration feature that is not implemented by this local application. Visual quality remains subject to the user's in-app review rather than a numeric parity claim.

## Improvements grounded in the audit

- **Reference corrections:** Kairo checks mapper data against the official SDE. Two effect-name conflicts, special-system names, C13/Thera shattered coverage and one effect percentage are corrected with recorded evidence; [reference provenance](WANDERER-REFERENCE-NOTICE.md) lists the details.
- **Unknown stays unknown:** Static badges never create live destinations. Imported diagrams do not acquire a fresh expiry simply because they were exported recently. Recorded ship mass is not a remaining-mass meter, and no recorded passages does not mean no one passed.
- **Safer scan reconciliation:** Partial/malformed scan input cannot silently remove omitted signatures. Deletion restoration preserves observation age and rejects collisions with newer data.
- **One operational truth:** Canonical Universe links/signatures are reused by the chain, notebook and route engine. Copied diagrams share connection conditions while retaining independent layouts and annotations.
- **Useful exit planning:** Dated real service references, current public reports and the real gate graph are searched together with explicit constraints. [Destination provenance](WANDERER-DESTINATIONS-NOTICE.md) records source dates, hashes and limits.
- **Local performance and interaction:** Persisted positions, bounded records, one graph traversal per destination request and finite camera transitions keep movement purposeful and avoid a continuous physics/render loop.

Named test files are evidence locations, not proof that every mouse path or private EVE permission was exercised. No private EVE command or remote message is executed merely to demonstrate parity.

The remaining partial rows and hosted platform boundaries above are intentional disclosures. They must remain visible in release notes; “all Wanderer features fully integrated” would overstate this build.
