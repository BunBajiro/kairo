# Wanderer destination reference data

`server/data/universe-destinations.json` is derived from the MIT-licensed Wanderer source at revision `6c5d43936e88f1d2acabc4d45fc82cbb67d4a08a`, under [`priv/repo/data/route_by_systems`](https://github.com/wanderer-industries/wanderer/tree/6c5d43936e88f1d2acabc4d45fc82cbb67d4a08a/priv/repo/data/route_by_systems).

| Category | Source | Generated by upstream | System references |
| --- | --- | --- | ---: |
| Blue-loot buyers | `blueloot.json` | 30 January 2026 | 113 |
| Red-loot buyers | `redloot.json` | 30 January 2026 | 93 |
| Security-status services | `ss_cleaning.json` | 3 February 2026 | 32 |
| Trade hubs | `trade_hubs.json` | 3 February 2026 | 5 |

The normalized catalogue retains all 366 station references, their exact names/IDs, upstream generation times and the five principal market markers. The 243 category/system rows are not 243 distinct systems; categories overlap. No vendors or service claims have been added. Tests verify all referenced systems against Kairo's official atlas. These are dated reference destinations, not evidence of current buy orders, prices, access or service availability. Thera/Turnur destination candidates come from fresh EVE-Scout observations, and high/low-sec exit candidates come from the official atlas instead of this file.

Rebuild reproducibly with:

```sh
python scripts/build-universe-destinations.py /path/to/wanderer/priv/repo/data/route_by_systems
```

The script checks the four SHA-256 values for the pinned input and embeds them in the generated catalogue. The runtime search constructs one graph using Kairo's normal route rules and performs a bounded multi-destination traversal. It never calls a vendor, fetches market prices or writes an itinerary. Routes respect selected chain confirmation/expiry, exclusions, vessel limits and explicit public shortcut choices. Ranking is by the chosen route cost, not schematic or physical proximity.
