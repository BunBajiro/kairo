## Selected dispatcher and map authority

Use only POST `/api/universe/jspace/maps/{map-id}/commands?character={owner-id}` with one canonical complete map segment and one positive safe decimal owner selector. Reject extra/trailing/encoded-separator path aliases, duplicate/conflicting query selectors, unsupported methods and body map/owner aliases. Decode once; source maps remain read-only. The common version1 object contains exactly `version`, `token`, `runtime_epoch`, `storage_lineage`, `owner_connection`, `map_incarnation`, `revision`, `op`, plus the operation fields below. Version is numeric1; opaque tokens/identities are nonempty bounded strings issued/validated by their owners; revision is the exact server-issued H1 base, never a client clock. Representation/length budgets require P0-04 review; no permissive string-to-number coercion is selected.

| Selector | Additional fields and meaning |
| --- | --- |
|170 `pilot.add` | Required numeric `character_id` and exact `target_connection`; target slot must be absent at current map base. No supplied row ID/tracking/baseline. |
|171 `pilot.tracking` | Required numeric `character_id`, `row_incarnation`, Boolean `tracking`; exact `target_connection` required for true, forbidden for false. Desired state, never a server-side toggle. |
|172 `pilot.remove` | Required numeric `character_id`, `row_incarnation`; no connection requirement for the target and no other operation fields. |
|173 `map.update` | Nonempty patch containing at least one of `name`, `description`, `scope`, `track_passages`; `scope_dependencies` required only when scope is supplied, as defined below. No roster/topology/child/undo/body-generated fields. |

Reject null/array/nonobject envelopes, duplicate JSON keys, missing/unknown fields, whitespace-altered/unknown operation names, wrong Boolean/string types, nonfinite/fractional/unsafe/zero target IDs and overflow before domain writes. Validate operation/schema **before** canonical reads with effects, expiry cleanup, index/source birth, undo clearing or partial mutation. Other recognized selectors retain separately pending operation schemas;090's shared guard is not permission to remove, implement or accept174–192. All callers must eventually enter the same authoritative owner.

Local editing requires the exact currently connected positive owner after full body receipt and at commit; optional location/fleet/log collection need not be enabled. Reauth may leave local notebook preference editable but cannot make samples eligible. Capture owner/target connection, lineage/runtime/dataset and required catalog/control dependencies; A→B→A is a replacement. A retired required identity before commit rejects uncommitted work. Browser/socket departure does not cancel admitted work. Guest0/source map/foreign map/missing or retired incarnation rejects; retained captured-owner metadata inspection after disconnect grants no editing authority.

Preserve H1's **one map incarnation/revision/latest safe receipt**, independent of interactive membership and H3's global source pointer. No new per-field CAS lanes. Concurrent tabs or tracking topology changes against the same map base conservatively conflict; a browser busy flag is insufficient. Every fresh successful command, including validated same-value patch/tracking, advances map revision/receipt. Same current token is conflict/readback without another commit, including changed payload; superseded tokens are never reused.

No names, descriptions, location samples, source notes, topology or private-content digest. The response's exact **saved result** is immutable; any later map projection/revision is labelled current and cannot replace it. Automatic topology writers advance map revision and explicitly supersede user attribution; baseline-only/freshness metadata advances a separate bounded snapshot dependency without forcing every stationary sample to invalidate editor CAS. Commands must reread and preserve current baseline metadata inside their transaction, never rewrite a pre-admission whole-map clone. H1 coherent copy/export uses the relevant snapshot dependency. This interface is not broad acceptance of automatic writers.

## Roster consent and baseline continuity

Each live roster row has a nonreused server-owned incarnation within the map and a separately versioned recipient continuity generation. Character ID is the natural slot, not the lifetime identity. Add allocates identity atomically; remove/re-add of the same character gets a new row and cannot accept old toggles/callbacks. There is at most one row per character. Reject malformed retained duplicate/invalid rows as unavailable/corrupt state rather than deduplicating away consent. Bound current row metadata; no permanent removed-row journal/tombstones.

Add and resume require the captured target currently connected, but not a ready location or EVE scope. Pause/remove work on the exact retained disconnected row while the map owner remains eligible. `tracking:true` requires current target connection even if already true. Same-value pause/resume against a valid exact row is evidence-only and never reseeds or replays. A real pause invalidates this recipient's continuity and clears its baseline; remove retires its identity/subscription. A real resume advances continuity and establishes a new baseline as below. Removing the owner or last row is valid: owner is not reinserted, empty roster means no subscribed tracking and does not delete the map. Create's H1 nonempty initial roster is a separate rule.

Roster tracking and map-level sampled-passage consent are independent of H3 global source-recording choice, selected map, G2 reader configuration and another map's consent. H3 clear/switch never pauses an independent interactive row. H4 never switches recorder, enables readers, fetches ESI/logs, moves navigation or makes a source map editable. A retained disconnected/reauth/module-ineligible target may remain tracking-enabled but unavailable; reconnect does not recreate its row or invent another command.

On add/real resume, capture at most one current local selected-location sample from the owning G2/producer identity. Admission requires exact target connection/runtime/reader/control generation, known current catalog system, ready/nonstale/unexpired time and the existing source-specific eligibility. Preserve source/observed/expiry values; invalid/unavailable optional location means waiting, not a fabricated successful sample or a failed consent save. Storage/corrupt required-state failure is an error, not ordinary no-location. Recheck authority/freshness at commit. This deliberately retains H4's explicit interactive baseline option; H3's source-selector command still never seeds a cached sample.

The cached seed is display/optional-card evidence only and cannot be either endpoint of an inferred movement or passage. The first subsequent producer observation captured after consent under the new recipient continuity establishes the traversal baseline; merely replaying the cached sample or delivering a callback captured before consent does not qualify. This explicit refinement prevents a fresh-looking pre-consent cache entry from bridging the inactive interval and requires new acceptance. Original source times are never changed. For an unrestricted map it may add the current wormhole card within existing limits; scoped baselines do not independently bypass scope to add cards. If the optional card cannot fit, save consent/baseline with explicit capacity-skipped card disposition, without eviction or coverage consumption. Row/cached-seed metadata/optional card commit inside the parent transaction; distinguish that seed from an eligible traversal baseline. No source/private notebook annotations are copied. Unavailable seed waits for a subsequent current-generation observation, which is baseline-only. Never bridge the pause, removal, owner/target disconnect, reader/source-policy change, reauth or runtime/dataset interval. A reconnecting retained row gets new current-runtime continuity before delivery; old callbacks cannot be relabelled current merely because IDs match again.

An effective scope change invalidates this map's recipient continuities and clears their baselines; subsequent eligible observations establish new baselines. An effective passage-logging change advances a separate map passage-consent generation; enabling cannot log a transition with either endpoint captured before that consent. It need not reset continuously valid topology tracking. Disabling immediately fences pending passage acceptance while retaining recorded passages. Same-value details do neither. Delivery rechecks row identity/continuity, map/passage consent and producer authority at final acceptance. Preserve recipient-specific dedupe from H3: resetting one map row/source cannot replay other subscribers' already committed sample or mark an uncommitted delivery consumed. Source topology generations/coverage, row continuity, passage consent and command revisions are distinct, not interchangeable clocks.

## Details patch and scope authorities

Select **patch semantics** at the server. MapForm must build its request from changed fields against its captured saved base; a full four-field submission is also valid but follows the same base and effective-difference rules. Omitted keys preserve current values; scope, when supplied, replaces its complete selector object rather than merging omitted groups. No empty patch. A valid nonempty same-value patch produces a no-op receipt without population or undo changes.

| Field | Selected normalization and clearing |
| --- | --- |
| `name` | String, trim; raw and normalized length≤80 UTF-16 code units; normalized nonempty. Empty/whitespace-only/null/wrong type rejects. |
| `description` | String, trim, raw and normalized length≤4,000 code units. Empty/whitespace-only clears; null/wrong type rejects. Align MapForm to4,000 and retain existing2,001–4,000 text on unrelated edits; never truncate to the old UI limit. |
| `track_passages` | Strict Boolean; false stops future sampled passage acceptance, true grants only the separate current consent boundary. Null/number/string rejects. Neither value deletes history or grants connectivity/access. |
| `scope` | Null explicitly clears to unrestricted. Object may contain only the six groups below; absent groups are empty, explicit group null rejects. Empty object/all-empty arrays normalize to null. Every supplied group must be an array; no unknown groups, scalar shorthand or silent invalid subset. |

Scope groups are `system_ids`, `constellation_ids`, `region_ids`, `alliance_ids`, `corporation_ids`, `power_bloc_ids`. Validate every raw entry before dedup, enforce existing2,000 entries per supplied group before duplicate removal, sort numeric groups ascending and bloc strings by deterministic code-unit order, dedup, and leave the submitted object unchanged. All groups plus command metadata must also fit the actual serialized150,000-byte HTTP envelope, including UTF-8 and JSON escaping; six individually valid groups need not fit together. Check raw request bytes in the browser and server; no silent cap increase, truncation or prefix admission. Numeric IDs are positive safe integers; system IDs require local catalog identity, constellations/regions require current K-Space membership (no J-Space organizational groups). Explicit wormhole system anchors remain allowed. Alliance/corporation IDs require shape, not present sovereign ownership. Bloc IDs must be exact configured explicit identifiers; inferred/alliance-derived groups do not qualify. OR applies within and across groups; unrestricted still requires a valid system identity.

`scope_dependencies` contains exactly current `catalog_generation`, `scope_policy_generation`, and `bloc_config_revision` only when a nonempty power_bloc_ids group is supplied. These are positive authoritative generation identities returned with the local editor basis, not display labels. Capture/recheck relevant generations before commit, including direct clients without opening the editor. Missing required catalog/config authority is unavailable, a changed captured generation is conflict, an unknown system/bloc against complete current authority is malformed input. Clearing scope needs current policy/catalog basis but no ready sovereignty or bloc resolution. Unrelated title/description/passage edits need not revalidate a retained unavailable scope as a new selection.

Geographic matching is independent of sovereignty. Ownership matching requires a current ready complete nontruncated sovereignty snapshot, and configured-bloc matching additionally uses current explicit alliance membership. Faction IDs, station ownership, inferred coalitions, private annotations and old visits are not sovereign corporation/alliance evidence. Missing/stale/incomplete sovereignty yields unavailable owner-match evidence, never unrestricted fallback or an assertion that no eligible chains exist. It does not reject saving valid explicit owner selectors. Later bloc/config/catalog changes change matching eligibility, not saved selectors or historical rows; removed/unavailable configured blocs match nothing until valid authority returns or a deliberate scope edit replaces them. Do not silently clear retained IDs.

Scope contraction/expansion/clear retains existing cards, archived annotations, connections, passages and child records; it does not purge outside history, renew lifetimes, confer provider access or replay old movement. Clear restores unrestricted **future** tracking; it does not bulk-copy every source. A scope contains anchors for eligible source-chain adoption, not a strict filter deleting every outside endpoint. The broader connectivity/movement algorithm remains pending.

## Atomic save, population and undo interface

The parent command is one short local transaction: recheck exact owner/map/row/base and relevant dependencies; apply validated patch/roster, recipient and passage continuity, optional add/resume baseline/card, undo disposition, map revision/latest receipt and bounded follow-up admission metadata together. Read current affected state inside that boundary. Required storage/write/commit failure rolls back all of these. No provider/filesystem await, all-map scan or canonical expiry maintenance belongs to admission. Use passive canonical evidence where needed. Separately due maintenance must be attributable to its owner and invalidate affected bases; a rejected/unknown selector cannot cause cleanup. Unknown actual commit outcome fences affected delivery pending inspection; it is not presumed rollback.

Select source population as **separately owned follow-up**, not part of the saved edit. A changed nonempty scope, successful add or real resume on a scoped map may admit one finite captured population pass for that exact saved map/roster/consent result. Name/description-only edits, same-value saves/toggles, passage-only changes, pause/remove and scope clear admit no backfill. Persist at most one bounded latest follow-up status per live map, associated with its initiating command and required map result/dependencies; no queue of old snapshots. Reserve capacity before parent acceptance or save with explicit population-not-admitted/capacity status. Never silently drop an admitted pass.

The pass captures finite local donor references for the consented connected roster: source incarnation and topology/snapshot generation, relevant connection/control eligibility, canonical dependencies, catalog, complete sovereignty/config basis and one evaluation instant. Source choice does not require the donor still be H3's selected recorder; retained genuinely live evidence from an eligible explicitly consented pilot remains separate from active recording. Missing donor/unavailable optional evidence reports none-available/unavailable; no incidental source birth/provider lookup/history reconstruction. Preparation over unreadable required donor data fails the pass explicitly, not a fabricated empty or invalid-subset success. Recheck captured recipient/map/roster/consent and relevant donor dependencies in the follow-up transaction. Changed authority retires that pass as superseded; no rebase onto later state or unbounded retry.

Use deterministic donor/component order and bounded indexed adjacency with visited sets. Preserve H1 whole-component capacity: copy a complete eligible component or skip it entirely with unconsumed coverage; no partial edge prefix, orphan cards, eviction or silently imported invalid subset. Classify expired/collapsed evidence at the captured basis and recheck expiry; expired components are explicitly omitted, never renewed. Preserve original ages, exact fresh destination link identities, unconfirmed/inaccessible state in both directions, existing destination private annotations and monotone source coverage. Never copy donor private notes/children/receipts, renew a locally earlier expiry, reset coverage after pause/re-add, or resurrect deliberately removed topology from already consumed old evidence. New genuine source generations remain distinguishable. Full graph equivalence/movement/fan-out algorithms require successor proof.

All selected fitting components, owned canonical copies, destination map/coverage, relevant authority and follow-up disposition commit in **one separate outer transaction**; storage/validation failure rolls that pass back as a whole while the prior saved edit remains committed. Domain partial capacity/expiry disposition reports copied/skipped counts and reasons. No silently successful partial storage write. Follow-up uses map CAS and advances/supersedes H1 map authority when content changes. Its latest safe result may retain the exact initiating parent token/base/result association and its own base/result, without inventing a second user command; it can prove that parent only while this bounded association survives. Later unrelated automatic/manual changes may supersede attribution. No per-pass receipt history or indefinite promised recovery. Restart retires any uncompleted pass as interrupted/unavailable; ordinary future eligible tracking may populate under its own authority, never by replaying the old command.

Report independently: **saved changed/no-op**, baseline admitted/waiting/card-capacity disposition, population not-required/not-admitted/pending/complete/partial/failed/superseded/interrupted, runtime application applied/pending/blocked and optional current projection. Once the parent commit is known, failed population/indexing/SSE/serialization/reload cannot call the save rejected or invite resubmission. Receipt inspection never executes population. A later deliberate same-value save does not serve as a retry control; normal subsequent source events retain their own pending contract.

Runtime indexes/subscriptions/dedupe and callbacks publish only after **actual outer commit**, never nested savepoint release. Install the committed eligibility fence synchronously before fallible notifications; obsolete recipients cannot deliver after pause/remove/scope/passage retirement. Failed application blocks affected delivery and permits bounded rebuilding from current committed truth, preserving unaffected H3 subscribers. Proven rollback leaves prior runtime state; uncertain commit blocks until resolved. No semantic travel/Session/alert event is emitted merely for editing consent/details. Child G3 manual lanes/content generations, G4/G5 authorities, H1 membership/birth/retirement and installation-wide Places remain untouched unless their actual owner makes a separately contracted change.

The required interface to pending192 is deliberately narrower than accepting its algorithm. Effective roster changes, scope changes or passage-consent changes **clear all annotation/layout undo entries** atomically and are not reversible by192. A mixed details patch containing any effective consent/scope change clears undo for the whole patch. Mere key presence/same values do not clear it. Changed name/description-only patches create a bounded field-scoped inverse naming exact map incarnation, changed fields and expected post-edit values/generation; later undo may change only those fields after current-base/field checks. Do not store/restore a whole map snapshot to undo H4 details. No-op leaves existing history unchanged. Automatic observations must preserve or invalidate an entry safely, never allow it to overwrite newer evidence.

All future192 paths must exclude roster/row identities, baselines/continuity, track_passages/passage consent, scope, source coverage, canonical/child evidence and receipts from snapshot restoration. Undo cannot recreate removed rows or reverse later live consent; historical records, consumed coverage and removed links/observations are not reversible through stale layout snapshots. H1 delete retires undo; H2 duplicate/import copies none. This selects a compatibility boundary and H4 undo disposition only; selector192's own validation, layout/node restoration and full implementation remain unaccepted.
