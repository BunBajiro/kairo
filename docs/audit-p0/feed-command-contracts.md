## Local config and manual collection

Use two independent logical entities: global feed config and global manual-storm collection. Each has persistent storage lineage, monotonic revision and one latest bound command receipt; initial defaults have an explicit virtual base without GET writes. Same-value commits advance their entity revision. Bind token to exact entity/action/base and validated intent under the shared rules; receipts contain safe metadata, not report text or a private-content digest. No per-report tombstone, per-click journal or browser-global ordering promise is needed for full replacement. Both storm routes enter this same owner/CAS path.

Validate exact paths/methods/envelopes before admission. Keep existing selector spellings only where they have defined semantics: reject unsupported/duplicate selectors, arbitrary URLs, `force`, pilot/map ownership fields and unknown command fields. Feed-specific callers must omit both `character` and `map_id` from query/body, including the generic operations mutation helper when a map is open; preserve other pilot/map command scoping. GET projections may identify their observer separately in UI, without making it an authorization scope. Config PUT supplies both boolean enable and integer window5–120; schema/version is protocol metadata, not an editable setting. No coercion, omitted-field read/modify/write or silent truncation.

For manual replacement select one canonical command envelope with required `items` and expected collection revision/token; POST import additionally identifies `kind:storms`. Empty `items` is an explicit clear. Every item supplies a stable bounded ID, positive safe numeric system ID, one exact storm type and explicit observation/expiry instants. The UI assigns the new ID once when accepting the submission; reordering/reading/retrying inspection cannot generate a new identity. One documented `manual:` prefix canonicalization is permitted; reject duplicate canonical IDs, unsupported fields, missing/invalid IDs or values that would be shortened/coerced. Canonical timestamps preserve the same instant and names may trim; a missing name may use the deterministic type label. Keep the current80-character ID/160-character name ceilings,32-item maximum and accepted four types as compatibility of intended controls, not lossful truncation. Strip display-only source/area/age/staleness fields in the client rather than trusting or storing them as submitted authority.

Validate the whole replacement before any write. Preserve original dated reports, including expired history; do not make old evidence fresh on import or silently evict reports to admit another. Bounds remain observation≤accepted wall time+5minutes, expiry>observation and span≤7days, with finite arithmetic. Select a strict supported timestamp form: four-digit year0001–9999, valid calendar date, `T`, hour/minute/second, optional1–3 fractional digits and `Z` or a valid signed hour/minute offset. Reject absent zones, impossible/normalized dates, leap-second spellings, excessive fractional precision and nonfinite instants; canonical UTC milliseconds must represent the exact submitted instant. New/changed centres require positive current local known-space classification with finite security≤0. Capture the atlas generation used for validation/derived area preparation and recheck it at commit. A replaced basis conflicts, rather than silently moving the footprint. An unchanged accepted centre/provenance can be retained during temporary catalog unavailability; removal/clear remains local. Retained canonical reports remain privately inspectable/removable after positively conflicting classification, but their conflicting or obsolete-generation derived footprints are ineligible for Atlas/route output even if the row is unchanged. Unavailable catalog data cannot silently recalculate or retarget that footprint; historical input is not current eligibility. Changing to another centre requires current positive evidence. A new report cannot claim eligibility through unavailable/unknown catalog data.

Use one short local transaction per command for authoritative values, revisions/provenance and receipt, with final base/eligibility checks inside the transaction before writes. Keep derived area preparation bounded and outside the transaction; retain a current generation-owned gate graph/index instead of rebuilding it for each report. Store canonical input separately from generation-bound derived output as needed; wire/storage encoding is an implementation choice. Return the exact committed config or manual collection plus revision/receipt, not `state()` or a later mutable config read. Required write failures roll back together; generic storage errors may leave an unknown result and require inspection.

After config commit, disabling combat immediately makes its subscriber/future intake ineligible before fallible notification/projection. Preserve its already committed cursor/data and unrelated Session subscribers. Enable/disable changes collection authority; window-only changes affect display and must not cancel healthy collection or invalidate compatible raw reuse. Re-enable creates current intake authority: an old aborted callback cannot become current merely because the boolean returned to true. Normal scheduler work can resume under its existing cadence; config Save itself is not Refresh. A stale config conflict has zero collector side effects.

Local storage success is separate from cancellation completion, feed invalidation, Atlas rendering and callback delivery. Manual-save success cannot be lost because `state()`/connection cleanup/reload failed. Emit bounded content-free private resource invalidation after actual commit; no new semantic event/toast replay is required. Module disable hides data but does not make the authoritative manual collection empty. Accepted valid local commands drain through their final transaction after browser/socket loss or admission close; actual stale bases/retired dependencies/deadlines can still reject uncommitted work. Neither view changes nor HTTP abort are rollback.

Extend GET `/api/universe/feeds/config` with coherent value/revision/receipt and caller-known current runtime epoch, storage lineage and module/combat-enable control bases needed before refresh admission. Select GET `/api/universe/feeds?inspect=manual-storms` for the **authoritative manual collection**, with optional `metadata=only`; it returns canonical rows/revision and latest receipt independently of module display. Select GET `/api/universe/feeds?inspect=refresh` with either exact `operationId` or the caller-known `token`, `runtimeEpoch`, `lineage` tuple for **refresh operation status**; the latter works when admission acknowledgment/ID was lost. Validate selector combinations exactly and label current controls separately from historical operation evidence. Receipt reads use coherent exact storage snapshots and never invoke `state()`, expiry writes, NPC observation, providers or full Atlas projection. Ordinary feed display may retain existing local expiry maintenance, but command attribution must not depend on it. One initial passive inspection follows an unknown/malformed/mismatched acknowledgment; missing/superseded receipt is unknown, not rejection. Later deliberate inspection is bounded; no automatic PUT/import/refresh replay. Normal restart preserves local receipts; fresh profile changes lineage.

## Finite refresh ownership and partial results

HTTP-116 is an explicit finite collection attempt, not durable configuration, a provider mutation, an all-data-refreshed barrier or a command to catch up indefinitely. Accept either all sources or one exact known source, plus a fresh token, caller-known runtime epoch/storage lineage and the relevant current control basis. Reserve finite operation/component capacity before any NPC/cache/provider side effect. Capture selected components, active atlas/source identity and relevant module/combat-enable authority; window-only config changes do not retire provider work. Recheck admission/control after body parsing and at each dispatch/publication boundary. Reject stale intent before side effects; disabled components have explicit skipped outcomes. No pilot connection capture is appropriate for these credential-free sources.

Use a bounded runtime operation registry and fixed per-source flight owners, not a durable job journal. Admission returns an exact operation ID/token/epoch, immutable selected scope and per-component dispositions. The existing awaited response may include terminal results when all components settle within the response budget; otherwise return pending with that same identity. Per-source states distinguish joined/started, fresh-cache or cooldown skip, disabled/retired, local projection/reference only, committed/revalidated, partial, failed and pending. Results name accepted cache revision/sequence prefix when available; a later full state is a separate current projection. Status absence after expiry/eviction/restart is unavailable attribution, not proof of no work. Restart may resume ordinary scheduled collection from accepted caches/cursor under normal controls, but never replays the old manual operation or success feedback.

Join only an existing compatible finite flight, recording that attachment without claiming a new dispatch or extending its original deadline. A repeated POST with a retained token and identical bound input returns its existing association only, with no new subscription, pass or deadline; changed input conflicts. Pure GET status never admits work. There is no permanent replay history after attribution expires: clients must never reuse a token or POST to discover its result. Repeated fresh clicks may join within aggregate limits; no per-click unbounded waiter chain, deferred force-refresh demand or automatic second batch. Mixed selections can have independent component outcomes; one provider failure does not undo another accepted cache. Source metadata, retry time and partial/gap status remain truthful. A selected campaigns/development/NPC-deltas/points action may project current local evidence, with bounded NPC-window observation where applicable, but must not silently call ESI/manual Sync or claim those provider snapshots were freshly fetched. The all-source UI retains its present all-source meaning.

Respect existing freshness, validated Retry-After/backoff and shared-provider pacing; explicit refresh, timeout, reconnect, another tab or diagnostics must not bypass a cooldown. This unit adds no automatic retry within an admitted pass. A provider-free skip remains a successful scheduling decision, not a fresh observation. Keep fixed target allowlists, credential exclusion, redirect rejection, streaming byte limits and complete schema validation before cache publication. Current12-second/2MiB limits and source TTLs are source baselines, not new measurements, final P0-04 budgets or proof of current upstream rate requirements. Before any provider-policy change, verify its primary documentation; do not infer a new provider guarantee from existing comments or fixture behavior. Invalid/overflowing time headers need bounded conservative handling, not NaN/Infinity deadlines or immediate retry loops.

Consumer cancellation detaches only that owner. Module/combat disable prevents unsent requests/next packet and retires obsolete refresh associations; it does not abort another eligible Session consumer, delete accepted samples or reset provider cooldown. Keep a retired task charged until its actual resources settle; observer timeout alone does not free capacity or permit overlapping replacement work. Shutdown closes admission, quiesces future dispatch, aborts owned reads and drains real flights before Store closes. Unsupported/uncooperative transport cannot be made settled by relabeling it cancelled; bounded failure status must retain occupancy until cleanup. No new cancellation UI/route is required for this unit. A browser disconnect detaches observation, not admitted shared collection or another owner's work.

Commit each accepted combat step's cursor and retained rows/status atomically. A valid filtered-out/duplicate packet can advance cursor only with an exact accepted-step result; a malformed packet cannot. Preserve the accepted prefix on later packet failure/cancel, with no skipped sequence or fabricated completion. Keep the finite packet budget plus any separately counted pointer request; a current-pointer reset records the gap and never claims historical recovery. Reference windows stay separate from personal Session accounting and cursors. A window edit retains raw history, and cancellation of Universe must not repeat or cancel Session accounting through shared transport.

For other sources, accept each complete normalized representation/validator/cache status atomically under its current source owner; late obsolete writes must not overwrite a newer accepted cache. A304 can reuse only its matching accepted representation and still filters expired links; a fresh body without ETag drops the old validator (EC-02). Last-good data remains available with honest age/status when a new response is invalid or unavailable. **After canonical cache commit**, dependent link-forget/navigation invalidation or notification failure is a follow-up failure: never restore the older representation or mark the already accepted body rejected. Immediate read/route eligibility excludes expired or revoked links independently of fallible cleanup; bounded idempotent cleanup converges from current canonical state without provider replay. This does not promote public reports into verified private links or remove independently confirmed private connections.

## UI, algorithms and cost prerequisites

Settings Save captures both the pilot-operations snapshot/base and the global-feed snapshot/base at invocation. The two current commands remain separate commits: report which half committed, rejected, unknown or was never sent; do not claim cross-owner atomicity. An unknown first half pauses the dependent second; an acknowledged first half plus failed/unknown second never authorizes replaying the first. Shared continuation rules govern any deliberately accepted successor. Pilot disconnect/remount can retire editor publication without rolling back global feed intent. The next operations-config contract must implement its own CAS/receipt/drain semantics before this combined UI can claim full acceptance; G1 does not silently accept that family.

Capture editor instance, exact entity, submitted snapshot/base and draft generation through settings, manual import and refresh. A→B→A edits still advance generation. Late acknowledgments/finally/error callbacks cannot clear or unlock a new draft, newly mounted editor or another operation. Known commit plus reload failure stays committed. Build a manual replacement only from the authoritative canonical collection/base plus the submitted edit; do not use the filtered display list as saved authority. Conflicts retain the draft for deliberate resolution, with no merge/rebase that silently overwrites another tab. Keep report identity/observation/expiry stable across uncertainty; clearing inputs belongs only to an attributable committed submission that still owns that draft. Chrome/Firefox must cover these real owners, including the sequential settings halves and disabled-module manual edit.

Retain source-specific information limits: attributed reports are not access, passage, remaining mass, confirmed destruction coverage or private route verification; NPC deltas compare distinct rolling snapshots and may be negative. Feed-cache membership, observation freshness and display expiry are separate. Reporting age can be computed from wall time; it is not authority to extend accepted expiry or bypass a cooldown. Preserve report timestamps across304/import: a repeated read/heartbeat, backward clock step or revalidation cannot revive an observation already expired/revoked or reset the same observation's accepted lifetime. Expired manual reports remain stale stored evidence until explicit replacement; expired public links cannot become usable again. The shared expiry/cooldown owner's non-extension mechanism, restart/clock policy and numerical tolerances are implementation prerequisites with explicit P0-04 browser/runtime evidence, not currently proved behavior or a pixel/real-time guarantee.

Measure cardinalities before implementation: provider row/body limits before normalization; total cached/string/derived-area bytes; worst-case32 manual and1000 provider storm expansions over dense/cyclic/duplicate gate graphs; source index reuse; dedup identity/sequence overflow; per-operation components/subscribers/retained results and total transport waiters; timer count, cancellation occupancy and shutdown latency. Keep bounded graph traversal with visited membership and no private-link expansion. Avoid repeated full atlas/history projections during quiet tick or status inspection. Current cap constants describe source baselines only; do not raise them or substitute per-request caps for aggregate proof. P0-04 must set request/component/operation/read/retention/CPU/memory/drain budgets and show healthy cold/warm counts plus fault saturation recovery.
