## Selected authority, identity and manual edits

Use exact routes/methods and strict versioned envelopes with fresh token, runtime epoch/storage lineage, explicit pilot/current connection or guest0, optional exact map incarnation, upgrade collection base and immutable payload. Reject conflicting body/query scope and extra path segments/unknown fields. Recheck captured authorization and current catalog/scope eligibility after body receipt and at atomic commit; A→B→A is a replacement. Disabling optional collection/alerts does not disable notebook editing or erase observations. Module/dataset retirement fences obsolete runtime work; no provider read belongs to this family.

Select **one durable upgrade collection CAS revision and latest safe receipt per pilot/scope incarnation**, independent of signatures, intel and settings. Stable initial bases require no GET write. Same-scope competing save/import/delete conservatively conflict even on different systems; other scopes remain independent. Every accepted command, including a fresh absent-delete disposition, advances revision/receipt atomically. Repeated current token is conflict/readback with no new write; equal values do not attribute an old request. Retained receipt has owner/action/token/base/result and bounded counts/target identity, not a payload copy or private-content digest.

Rows have nonreused server-issued identity/incarnation and unique normalized `(system_id,slot)` in their scope. Explicit edits name the exact live row; natural-key upserts capture its exact observed identity or slot absence against the base. Never choose a newly recreated slot occupant after preview. Same-scope system/slot moves remain permitted only if destination is eligible and free; scope changes require separate Maps orchestration. Delete/recreate receives a new identity, so old edits cannot resurrect or overwrite it. Unmentioned slots are retained by import; there is no replace-all, implicit deletion, clear-all or restoration command.

Strict manual fields: positive known system ID, integer slot1–100, integer level0–5, Boolean online, nonblank trimmed name≤240 without tabs/CR/LF, notes≤2,000. Text values must be strings; reject null/wrong types, nonfinite/unsafe values, overflow and unknown/generated fields rather than coercing/truncating. Use the same trim-only canonical text rules in preparation/save/import/export: retain literal markup as plain text, allow the full240-character server name bound, and never further truncate a reviewed value. SMT’s documented whitespace grammar/representability limit is separate. Catalog resolution is local and bound to one positive generation. Preserve manual multiline notes; formatting labels do not become game verification. Return all normalization and the exact target identity.

For an existing target, omitted fields preserve that target's values; explicit empty notes clears them. Resolve the target **before** applying defaults, including natural-key upserts. This selected consistency refinement changes the current omitted-level natural-key path that defaults to1; it needs requirement acceptance, not a retroactive bug claim. New manual records require system/slot/name, default level1/online:false/notes:''; existing UI sends its explicit values. A changed name/level/online updates only this local note. updated_at is server acceptance time, not evidence of a fresh provider observation. Ordinary save/import cannot set UUID, receipt, source timestamps or imported historical provenance. Native map provenance stays owned by its separate import contract.

## Preview and fully valid import

Select one exclusive source per request: text string or upgrades array; reject both/neither, wrong types and unsupported fields. JSON text may be an array or object with upgrades and optional version1; reject other versions and unknown wrapper/row fields. Rows use either numeric system_id or exactly one string system/system_name alias, resolved as an exact case-insensitive local name; numeric-looking names stay names and conflicting aliases reject. JSON slot/level are numbers of the required integral ranges, online is Boolean; omitted level defaults0, omitted notes defaults empty, null rejects. No numeric-string/Boolean coercion. SMT uses its defined decimal-token grammar and same range/name/uniqueness checks, preserves initial BOM/comments/known-header behavior and exposes interpreted fields in preview.

Preserve actual-content autodetection when format is omitted. An optional format hint must be smt/json; it does not reinterpret contradictory bytes. The canonical **detected format** and resulting notes policy are returned visibly with the preview and bound to the import recipe; UI must adopt that actual interpretation rather than present an SMT-preserves-notes review for JSON-clears-notes input. Explicit import carries expected detected format and exact captured source/base/dependencies; a mismatch rejects before writes. This retains paste autodetection without allowing format ambiguity to change meaning between review and commit.

| Manual existing-row edit/upsert | Omitted preserves; explicit empty clears | Omitted preserves selected target |
| SMT import | Always preserve matched notes; new row empty | Level absent→0; Online/Offline required |
| JSON import | Omitted or explicit empty→clear; supplied string replaces | Level absent→0; Boolean online required |
| Native map transfer | Separate historical copy/import contract | Preserve validated historical values; no new live authority |

Preview uses one coherent scoped snapshot, exact catalog/parser generation and shared preparation logic. Return normalized rows, matched identities/absences, added/updated counts, field/note changes and bounded line diagnostics, including explicit note clearing. No row/revision/receipt write, ID reservation, map assembly, config effect, cleanup, provider or filesystem work. Read-only map preview remains allowed without authorizing import. There is no durable preview cache. Import recomputes the immutable recipe against the captured base/dependencies; stale base/catalog/parser rejects with zero changes even if row counts still match. Direct HTTP import may omit a prior preview call but must carry current base/dependencies and gets identical validation.

**Any invalid row, duplicate system/slot, unknown header/system, capacity violation or malformed JSON rejects the entire import.** Do not copy G4's usable-subset semantics. Empty/comment-only/empty-array import is invalid; empty export is valid and must not be described as a command to clear the notebook. No prefix of an oversized array/text/line budget is admitted. Preserve1,000 total live rows per scope and at most1,000 imported rows as source ceilings, subject to aggregate budgets. Preview/import's1,000,000 raw HTTP-byte cap and1,000,000 domain code-unit cap are separate; JSON overhead/UTF-8 count against raw bytes. Manual save retains150,000 raw bytes. All applicable limits must pass; no implicit cap increase.

Bound **raw physical lines/characters, headers/comments, array entries, diagnostic counts/bytes and duplicated raw echoes** before admission, not only normalized records. P0-04 must choose these additional numerical limits and output truncation policy before implementation; capped diagnostic output must explicitly signal omitted details and cannot turn invalid input valid. Parsing errors are bounded input diagnostics; storage/IO failures are never misclassified as malformed rows. Do not echo private pasted text into diagnostics logs. Reuse catalog indexes and one natural-key scope index, avoiding repeated full-atlas/scope construction for each row.

Preserve the existing full-valid savepoint guarantee and extend it: all normalized row merges, capacity/identity checks, collection revision and receipt commit in one short local transaction, with one captured server acceptance time. Any required write/outer-commit failure rolls everything back. Publish/invalidate only after the **actual outer commit**, not a nested savepoint release. Return exact command counts/result revision separately from an optional current notebook projection and later publication/reload status. A postcommit error cannot turn a committed import into rejection or authorize resend. No new semantic event is required solely for a receipt.

## Delete, external writers and private export

Delete captures exact row incarnation/base, atomically removes it and records deleted/already-absent disposition. Absence observed now does not prove an earlier delete completed and does not reserve a never-created slot. An unsent stale update cannot recreate the removed UUID; a later explicit create uses new identity/current base. No signature-style24-hour trash or Maps annotation undo is introduced for upgrades.

Every Maps copy/import/delete writer must participate in upgrade collection authority in its actual encompassing transaction. External user commands atomically associate safe signature-independent upgrade receipt metadata with their exact outer token/owner and upgrade base/result alongside map receipt/revision; automatic retirement must explicitly supersede evidence without forging a user receipt. New scopes/copies receive fresh scope/row incarnations and no copied tokens/receipts. Historical fields/notes may survive a native transfer, but imported provenance cannot assert live structure status or renew alert/route authority. Map deletion retires records/receipts atomically; annotation undo must not resurrect deleted records or old command bases. These are dependency requirements, not broader Maps acceptance.

HTTP107 exports one coherent **current** pilot/scope snapshot, optional exact local system and selected smt/json format under read authorization. Validate exact query fields, map ownership/incarnation and catalog basis. Capture result rows/revision once; don't mix scopes or refetch during serialization. Export is read-only and provider/filesystem/map-cleanup free, with bounded row/output bytes/deadline/concurrency. Read-only owned source maps may export their own available scope; omission never falls back from a requested map to global. Scope/incarnation/revision metadata may be carried outside the portable payload; exported files contain no command tokens, private config, credentials or unrelated pilots/maps. Export is not mutation reconciliation.

JSON version1 exports normalized system/slot/name/level/online/notes; no UUID/map/timestamps/receipt, so it is a notes interchange snapshot, **not** a full historical map backup. SMT intentionally omits notes and preserves its existing disclosure; select a representability check: format candidate text, parse it through the same bounded grammar and compare all projected canonical values excluding only notes. Numeric-suffix names with level0, whitespace or other grammar ambiguity must not silently change the exported observation. Unrepresentable SMT is an explicit failed export with no success attachment; JSON remains the lossless normalized-value option. Deterministic ordering and catalog-dependent names require a declared comparison/tie policy before implementation; do not promise cross-runtime byte identity from current localeCompare.

If a retained row’s system becomes unresolved after a runtime catalog replacement, keep its stored evidence and identity; never silently drop it, reinterpret its numeric ID as a name, or attach it to another system. Both JSON and SMT exports containing that row fail validation with no partial/empty-success attachment; JSON is a fallback for SMT representation limits only, not for unresolved catalog authority. Exact-ID deletion remains available against the current scope/base without resolving the deleted row’s old system. A deliberate edit may explicitly remap it to a currently valid system/free slot using its exact identity/current base; an edit relying on the unresolved old system rejects without mutation. Other valid rows may still be edited/imported without deleting or rewriting the unresolved row. This is fresh runtime catalog handling, not legacy migration.

Lossless exported values do not guarantee single-request re-import:1,000 valid rows with2,000-character notes can exceed the unchanged1,000,000-byte import body limit, and wrapping exported text in JSON adds escaping/envelope bytes. Select bounded complete exports that may exceed that import limit when the separately approved export budget permits; such snapshots are not eligible for one import request. Do not silently truncate, split, raise ingress caps or claim a complete transport roundtrip. P0-04 must predeclare export capacity and test actual encoded import-envelope boundaries; this unit adds no large-snapshot/chunked import protocol.

Formatter validation/serialization/size failures must become explicit non-success HTTP responses before success headers, never a200 empty file indistinguishable from a legitimate empty notebook. Successful empty scope is explicit via bounded count metadata and valid empty serialization. Keep current note-omission feedback available to copy/download paths; output delivery/clipboard permission errors do not mutate the notebook or imply failed saved notes. A browser download and a prior copy are separate current exports unless deliberately using the same captured bytes; do not claim snapshot equality across two fetches. No public Stream publication or automatic transfer is authorized.
