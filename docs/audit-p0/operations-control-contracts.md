## Selected configuration contract

Select **one complete authoritative configuration entity per pilot, including guest 0**, with a server revision/latest receipt under storage lineage. Both writers submit immutable full snapshots against that entity's exact base; no hidden patch/merge and no cross-tab last-writer-wins. Missing storage exposes a stable virtual default base bound to lineage, pilot and the supported default-schema identity, without a GET mutation. The first save CASes that absence/default base; later commits, including same-value saves, advance nonreused revisions. A complete config/receipt commit is one short local transaction, with final entity/base/input checks inside it and no filesystem/provider await in the transaction.

The command envelope carries exact pilot, caller-known runtime epoch/storage lineage and connection identity (no connection for guest 0), expected config base and a fresh command token bound to the immutable validated full config. Current private authorization and positive-pilot connection are required **at domain admission after body receipt**; guest 0 remains supported without logs/fleet. A stale body-era connection cannot admit work for a replacement login. Once a valid local save is accepted, a later disconnect or observer retirement alone does not undo its pilot-owned preference intent: it may finish against its captured entity/lineage/base while collector authority and obsolete editor publication remain fenced. This does not add disconnected-pilot editing; only retained exact config/receipt inspection is permitted after disconnect. Config editing remains available while Universe is disabled; desired values do not become the derived module-off projection.

Validate an exact complete config shape/version and known fields before mutation; preserve supported booleans, `esi`/`logs`/`prefer_esi`, units and bookmark semantics. Reject wrong types, unknown fields, nonfinite/fractional/out-of-range numbers and lossy overflow rather than coercing/truncating. Documented trim, empty-line removal, stable list deduplication and sorted watched-ID canonicalization remain allowed and are reflected in the result. Raw editor input must validate before conversion; malformed comma-separated IDs cannot disappear before HTTP validation. Preserve current meaningful ceilings: nonempty directory strings at most 1500 characters, absolute with no NUL; four keyword/channel lists at most 32 entries of 100 characters; at most 100 known positive safe watched-system IDs; danger 0–20 jumps, report lifetime 1–1440 minutes and alert cooldown 0–3600 seconds; return symbol at most 32 printable characters. Preserve the bounded template/mapping validators in [`universe-signature-bookmarks.mjs`](../../components/kairo/universe-signature-bookmarks.mjs). Raw/normalized aggregate limits remain P0-04 work. Logs require a nonempty selected directory/channel set; saving a path does not prove it exists or is readable. Validate watched IDs against a captured current local catalog and recheck its basis before commit, without provider lookup or per-command full-atlas scanning.

The bookmark editor must obtain **authoritative config plus base**, then capture that full snapshot with its four formatting edits. Never spread effective `state.config` into a save. It uses the pilot-wide endpoint, which rejects `map_id` in body/query; map identity still owns its presentation, not the preference entity. Concurrent settings/bookmark writes from the same base yield one commit and one explicit conflict with the submitted draft preserved; no silent fresh-read merge. Shared current-token repetition is conflict/readback with zero new commit. No permanent journal, hidden content digest or per-click history is needed.

Return the exact committed config, base/result revision and receipt separately from reader/fleet application or notification status. A retained matching owner/lineage/token/base/result tuple proves the local commit; equal values, a different token, absent/superseded evidence or a failed read do not prove rejection. Select GET `/api/universe/operations/config?character=<id>` as the coherent authoritative value/base/receipt read, including current runtime epoch, connection and relevant control bases needed for refresh. Select exact `inspect=receipt` mode for bounded entity/revision/latest-receipt metadata only; it permits inspection of a previously admitted retained entity after disconnect; absence/unavailable evidence is explicit, never a newly fabricated proof of noncommit. This read does not call broad `state()`, configure readers, stat directories, refresh providers or assemble a map. One initial passive read follows an uncertain acknowledgment; later deliberate inspection is bounded, with no automatic PUT replay. Restart retains local receipt/lineage; profile reset changes lineage, and browser loss does not replay lost drafts.

## Persisted intent versus reader and collector effects

After commit, synchronously invalidate any **changed relevant collection authority** before fallible status/invalidation callbacks. Command revision is not itself an effect identity: bookmark/alert-only saves must preserve unchanged reader offsets/partial decoder buffers and eligible fleet work. Log enablement, directory, listener/connection and monitored channel set determine reader incarnation; module/connection/reauth retirement fences unsent reads and obsolete delivery even if booleans later return to their old values. Location-source changes immediately affect which observations may support location, without refreshing source timestamps or silently replacing ESI/OPSEC state. Reconfiguration that genuinely changes a reader establishes a fresh EOF baseline rather than replaying historical warnings.

Track desired versus applied reader generation and bounded waiting/watching/unavailable/error/disabled status independently of the durable config receipt. Apply the latest committed eligible config after an interruption through bounded owner reconciliation; do not resend the save. A filesystem permission/path failure leaves the saved preference intact with an honest local effect status, not a false failed-save result. A fallible `onStatus`/resource invalidation must not block the immediate disable fence or cause duplicate activation. Restart re-establishes only currently authorized readers with EOF baselines. No historical log backlog, transient warning replay or new semantic event is required to repair config application.

Retired readers remain charged until actual filesystem calls and admitted callbacks settle; replacing an entry or expiring a waiter is not cancellation of native I/O. Prevent obsolete readers from committing newly ineligible observations after a relevant fence, while preserving already committed valid records and unrelated readers. Do not claim a universal rollback/transaction for downstream intel/alert records in this unit: their accepted-record semantics remain HTTP-099–111/P1–P2 obligations. Disable/close may request supported cancellation, but must retain dependencies until actual work ends or report a bounded failed handoff. The dataset activation gate also applies to startup readers/collectors.

Fleet opt-in/off, operations/module enablement and connection/access changes have distinct collection authority. Save does not itself fetch a fleet. A false→true opt-in may release local admission delay as intended, but **never** reset a provider embargo. Separate local per-connection cadence from provider-owned cooldown scope; retiring old connection A cannot impose A's private cadence on B, while an applicable provider floor survives toggles/tabs/reconnect. Preserve cache/conditional reuse and existing shared ESI pacing; a manual refresh adds no extra automatic pass or retry loop beyond the shared transport’s separately bounded policy. Clock anomalies and malformed retry deadlines require the shared bounded non-extension/cooldown policy before implementation; current 60-second constants are source baselines, not measured P0-04 budgets or new provider guarantees.

## Finite fleet refresh contract

HTTP-112 remains one finite pilot-owned read attempt, not fleet mutation, an all-pilot sync or an indefinite request to follow future logins. Add a strict body envelope containing fresh token, caller-known runtime epoch/storage lineage, exact pilot/connection and relevant module/operations/fleet-enable authority. Optional map scope is validated for this caller's presentation; it does not partition fleet collection or grant fleet access. Recheck after body receipt, reserve aggregate operation/waiter capacity before any provider work and capture immutable owner/control identity. Unrelated alert/bookmark edits do not invalidate compatible fleet demand. Guest/disabled/missing-scope/reauth cases report explicit no-dispatch dispositions; private access loss cannot expose a retained roster as current.

Use bounded runtime operation attribution and one active collector per pilot. A compatible same-connection caller attaches to the existing finite flight without extending its deadline, adding another pass or refreshing cooldown. A caller captured as connection B may wait for older A's actual work to drain and then attempt B admission once, preserving the healthy PBR-25 replacement case. If B becomes C while waiting, B retires: it never recursively adopts C. Bound waiting generations/subscribers across all clients; new explicit C intent or the normal scheduler owns later work. No hidden force-refresh queue or global wait-for-idle barrier is introduced. Timers preserve one-due-pilot round-robin fairness. Preserve the existing `noSync` distinction: it skips scheduled fleet requests only; local log-tail ticks and explicit fleet refresh remain allowed under their normal controls.

Preserve an awaited HTTP result within the response budget: return created/joined operation identity and terminal component dispositions when settled, otherwise pending with that same identity. Distinguish admission, cache/cadence/provider-cooldown skip, membership, commander authorization, roster, public-name enrichment, accepted snapshot, stale fallback, retired, failed and pending. A cooldown/cache result does not claim a fresh ESI observation. The exact operation outcome/accepted snapshot identity is separate from an optional **current** map projection; map deletion, pilot retirement or reload failure after valid snapshot commit cannot reclassify the completed read. Bound each phase and retain component evidence sufficient to avoid presenting another flight's later roster as this response's result.

Select GET `/api/universe/operations?inspect=fleet-refresh` with either exact `operationId` or caller-known `token`, `runtimeEpoch`, `lineage` for passive status (validate mutually exclusive selectors exactly). The registry/status retains bounded component/outcome metadata and accepted snapshot identity/revision, not a copied member/name roster or private snapshot history. An optional current roster response separately rechecks present connection/scope/control eligibility and is labelled current, never the historic operation result. No filesystem/provider work, name hydration, config application or broad map projection occurs. Same retained token plus identical bound POST input returns only its existing association, with zero new subscription/pass/deadline; mismatched input conflicts. Clients inspect with GET, never repeat POST to discover outcome. Lost admission acknowledgment, eviction or restart may leave attribution unavailable; a current cached roster alone is not proof of the old manual command. Normal scheduled collection may resume under current controls after restart, without replaying old refresh intent or feedback.

Validate each provider representation before cache publication and retain connection, scope, relevant control and source identity through membership, roster and name awaits. Preserve commander-only member visibility, bounded roster normalization, and last-good stale fallback only under the same currently eligible owner/fleet; role/access loss or a known different fleet clears member visibility. A post-snapshot `changed`/projection failure is a follow-up error, never a reason to restore an older roster through the provider-failure catch. Atomic accepted snapshot/owner metadata is authoritative; ambiguous storage results require bounded exact local reconciliation, not a second provider pass or fabricated fresh success. Public name data cannot renew private authority. Detailed roster/parser/expiry algorithms remain separate audit work.

Browser departure detaches observation, not an admitted shared read or another caller. Explicit control/access retirement prevents next dispatch and obsolete publication; shared provider work is cancelled only where its owner permits without harming eligible consumers. Closing admission quiesces timers, aborts supported owned reads, drains actual collector/tail work and **accepted local config continuations** before Store/ESI close. A response deadline or terminal observer status does not prove the collector released resources. No new Cancel button/endpoint or durable refresh journal is required.

## UI ownership, existing proof and new gates

Capture pilot/connection, editor instance, complete submitted snapshot/base and draft generation for both editors; A→B→A still advances generation. Initial reads, passive refresh, Save, optional reload, error and finally callbacks verify their exact owner before changing drafts/busy/error/notice. A dirty authoritative base stays attached to its submitted intent; incoming state cannot replace it or reset bookmark fields while edited. A current clean editor may adopt new authoritative config. Existing mounted busy protection plus CAS is sufficient; no new general save queue is required. Bound accepted snapshots across remounts. A genuinely accepted dependent successor follows shared known-predecessor rules, never silent rebasing over another tab.

The combined settings Save captures both Operations and global-feed snapshots/bases **at invocation** and retains two distinct outcomes. Known Operations commit followed by failed/unknown Feed PUT must not replay Operations, label both saved or discard a newer draft. Unknown first-half outcome pauses the unsent second half; proven first-half commit can release its already accepted continuation under G1. A known commit followed only by local reload/effect failure stays committed. Synthetic pre-owner 503 proof is not proof that any 503 or transport loss means noncommit. Config's pilot/map presentation retirement must not retarget the global feed half. Keep browser-local sound/volume/permission effects separate; their storage failures, audio resources and operational-alert feedback ownership belong to the browser-local/P0-03 inventory, not either durable receipt. Log paths, names, channels and text are private; diagnostics use bounded redacted metadata, with no automatic telemetry or new logger.
