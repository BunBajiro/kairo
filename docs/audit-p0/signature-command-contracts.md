## Selected identity and authoritative writes

Use strict versioned envelopes and exact routes/methods, including exact single DELETE ID path. Capture token, caller-known runtime epoch/storage lineage, pilot/current connection (guest explicit), optional map identity/incarnation, signature collection base and immutable input. Reject conflicting body/query scopes and unknown fields. Recheck required authority after body receipt and at commit; A→B→A connection/map replacement is not the original owner. Notebook records remain editable when optional fleet/log/alert collection is off; disabling those collectors does not erase or invalidate local observations. Module/dataset retirement still fences obsolete runtime work. No provider lookup or refresh is part of any command.

Select **one persistent signature collection revision and latest safe receipt per pilot/scope incarnation**, covering live records and trash together. Stable initial bases require no GET write. This deliberately conservative CAS serializes signature edits/import/delete/restore in one scope, including different systems; other pilots/maps and unrelated intel/config do not conflict. Every accepted command, including a proven fresh absent-delete/no-usable-import disposition, advances this revision with its receipt. Repeat tokens conflict/read back without mutation. Map commands, map import, link retirement and trash cleanup that alter these records must advance the same authority in their actual outer transaction. External user commands, including Maps190/191, must atomically write a safe signature receipt/association bound to the exact outer command token, owner and signature base/result alongside that command’s map revision/receipt; authority advance alone does not attribute an uncertain command. Automatic link/trash cleanup must not forge a user receipt; it supersedes attribution explicitly, retaining at most the bounded latest evidence. Clock passage alone does not advance CAS, so restore expiry is also checked at commit.

Rows have server-issued nonreused observation identity/incarnation bound to lineage/pilot/scope; clients cannot create a chosen UUID. A reviewed upsert captures either the exact existing identity or the absence of the normalized system/code slot against its base. Never silently choose a replacement that appeared after preview. Explicit edits name the exact live identity; code changes must preserve uniqueness. Preserve existing same-scope system moves, but validate both old and new system and return the resolved move; an old-endpoint binding no longer resolves unless the observation still belongs to that endpoint. Moving a row neither moves a link nor creates/reconfirms access. Scope transfer is a separate Maps operation, never a body edit. Deleted/recreated same-code rows have new identities; restoring an exact deletion retains the original observation identity and uses a new collection revision.

Validate booleans, integer IDs, all known fields and maximum lengths before any write; reject lossy truncation/coercion and nonfinite/unsafe numbers. Scanner markup stripping and trim remain explicit canonicalization, shown in preview; enforce raw-field bounds before normalization so stripping cannot hide overflow. Keep code normalization/trim and accepted pattern `[A-Z0-9]{3}-[0-9]{3}`, string ceilings240 for group/type/name,2,000 notes,80 temporary name,64 chain labels, bookmark index0–1,000,000, and known four-character hole types. Empty/manual clearing versus omitted-preserve is explicit in the normalized result. Destination must be another valid system; non-Wormhole clears hole type/destination. Do not accept client-owned observation timestamps, generated identity, receipt, route conditions or imported-history provenance on ordinary save. Supplied read-only fields must be removed by UI request construction, not silently trusted.

Capture one positive catalog/parser-policy generation. Bookmark allocation depends only on the relevant G2 allocation basis (`bookmark_start_at_zero`), not unrelated alerts/config edits. Preserve existing indices and scan retained live/trash deterministically; no eternal sequence reservation is promised after bounded trash retirement. Return actual assigned index. Metadata edits preserve first/last seen and missing; explicit mark-present or scanner input is a new observation, mark-missing does not invent a scan. Capture one server observation instant per import; restore never refreshes it. Backward/future clock policy, including imported historical ages and restore expiry nonextension across restart, must be fixed under P0-04 before implementation; wall-clock strings alone are not revision/identity evidence.

## Pure preview and finite import

Select stateless preview: validate the full bounded source recipe, compute the exact canonical usable rows/classification/diff against one coherent collection base, and return that base, scope/catalog/parser/allocation dependencies and input association. No write, receipt advancement, ID/index reservation, expiry cleanup, semantic event, config application or provider/filesystem effect. Invalid input returns diagnostics, not partial mutation. Preview of a read-only map remains permitted but explicitly cannot authorize import. Known row invariants, normalization, capacity and eventual import validation use the same preparation logic; preview must show kind changes and other effective differences, not only the current group/type/name list.

No durable preview cache or permanent payload digest is selected. Import submits the captured source recipe/dependencies/base; server recomputes it and validates all target/slot preconditions. UI ties the review to the exact immutable recipe and generation; it cannot apply a previously displayed diff to changed text/flags/system/map. Stale base or relevant catalog/policy/allocation change conflicts with zero mutation, even if recomputed row counts happen to match. Direct HTTP import remains possible against a current base without an earlier preview call; it receives the same normalized disposition and validation.

Preserve usable-subset imports for within-budget malformed rows: diagnostics identify accepted/ignored/duplicate/error lines and `complete_scan_applied=false` whenever any error remains. UI keeps its existing refusal to import invalid review. Select first valid occurrence of a code, with explicit duplicate diagnostics; conflicting duplicate values are errors that suppress complete-scan marking, avoiding silent complete-scan authority from contradictory input. Skipped anomalies are warnings and cannot mark unseen anomalies missing unless inclusion was explicit. A wholly unusable bounded input returns no-usable-rows with zero row changes and attributable command disposition. Complete scan means mark eligible unseen rows missing in the captured **one system/scope**, never delete or replace the notebook. Blank scanned name/type preserve known values; retained notes/bookmark/hole metadata survive, except fields explicitly invalidated by an effective type change. No discovered destination is a route.

**Input overflow is rejected before subset admission**: do not import the first1,000 lines of an oversized request. Retain1,000 physical lines as the parser ceiling: split on LF (accept CRLF), exclude exactly the one final empty split segment produced by an optional terminal newline, and count every other line, including blank/whitespace-only lines, before duplicate/anomaly filtering. Thus1,000 rows with one terminal LF/CRLF fit; another blank line exceeds the limit. Bare CR is not a line separator. Preserve default150,000 raw HTTP bytes for now and domain200,000 code units as separate ceilings; the effective API must satisfy both, including UTF-8 and JSON overhead. P0-04 must reconcile/publish these limits, diagnostic/output bytes and aggregate concurrency before implementation; this contract does not silently raise ingress limits. Within those bounds, validate every consumed field; discarded signal/distance fields do not confer domain authority.

Commit the entire prepared usable subset, all missing changes, capacity/index allocation, collection revision and latest receipt in **one** short local transaction; a storage failure rolls back the whole subset. Parser-level partial acceptance is explicit and deterministic; storage-level arbitrary prefix acceptance is not selected. Bound staging before admission, reuse a scope index and avoid calling a full-scope scan/publication per row. Publish once after actual outer commit; nested Maps savepoint release is insufficient. No new signature semantic event is required merely to store a receipt. Return exact added/updated/missing/ignored/duplicate/error counts and local disposition separately from later projection/publication outcome. A committed import followed by lost response or reload failure stays committed.

## Delete, restoration and Maps dependency boundary

Delete names exact row incarnation/base. Atomically move its complete canonical observation into bounded trash with fresh nonreused deletion revision, original scope/identity and fixed delete/expiry times; include deterministic trash eviction and receipt in that transaction. A fresh current-base absent-delete may record already absent but cannot prove an earlier unknown delete or reserve a never-created identity. Sequential bulk UI deletion remains **separate commands**, not a batch transaction: retain committed prefix, one possibly unknown item and unsent remainder; stop on conflict/unknown and never label every unacknowledged item retained. Only an accepted known predecessor may supply the next captured continuation base under shared semantics.

Restore requires exact deletion revision/identity, current collection base, same live scope incarnation, current catalog eligibility, available capacity and both UUID/code slot free. Consume trash and write original observation plus restored_at/revision/receipt atomically. No rescan, overwrite, missing reset, new alert or renewed route/lifetime. Re-delete creates a new undo token; old token cannot restore. Keep current100-deletion and24-hour **maximum** availability, subject to earlier deterministic eviction/explicit retirement; expiry must never become eligible again after observed expiry because the clock goes backward. Missing/expired/evicted tombstone is unavailable restoration evidence, not proof of the outcome of a past restore. Normal restart retains committed receipts; fresh profile changes lineage.

Canonical Operations records own observation metadata; canonical links own connectivity/conditions. A signature destination, type, restore or scan must not create/confirm/extend a link. Binding uses exact observation identity and endpoint; restoring that observation may resolve an unchanged still-live binding, while reused code, changed endpoint or retired link cannot attach or resurrect. Link deletion/expiry must retire exact bound live/trash rows and collection authority atomically; it cannot leave restorable evidence that revives retired observations. Unbound/new same-code observations survive. These integration obligations require later actual-owner acceptance.

Maps190 must eventually validate both map revision/incarnation and signature collection base, and commit signature+optional binding+map revision/undo-clear together.191 needs the same cross-owner discipline;192 must never restore signature records/receipts, dead links or consumed trash through old annotation snapshots. Map import/duplicate use new scope/row identities, preserve historical ages/missing provenance and cannot copy command receipts or scan freshness. Map deletion retires all scope evidence atomically. Existing read-through cleanup/uncharted-record behavior must remain explicit; do not substitute ordinary map GET for passive inspection. **None of these obligations accepts selectors190–192 or the remaining Maps commands here.** The old `migrateMapScopes` compatibility path is outside fresh-profile acceptance; no legacy migration obligation is introduced or historical proof removed.
