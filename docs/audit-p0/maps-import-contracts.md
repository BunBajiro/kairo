## Strict supported portable schema and bounded preparation

Select exact methods/path/query and strict versioned command envelopes. Preview requires explicit connected positive pilot/current connection, lineage/runtime epoch and immutable document/name recipe; import additionally carries fresh token and H1 interactive membership base. Reject conflicting owner selectors, unknown command fields, client-chosen destination identity/receipts and wrong types. Recheck captured owner, required runtime/module/dataset admission and bases after body receipt and at commit; A→B→A replaces authority. Optional collection-off does not disable local notebooks. No provider permission is invented by a file.

Keep explicit native `format:'kairo-jspace',version:1` and the supported Wanderer-v1 adapter (`version:1` with absent native format and required map/systems/connections). This is Kairo’s bounded adapter contract, not a claim of compatibility with every current third-party application/schema. Reject other formats/versions and mixed schemas. Optional format selection must agree with bytes. Native wrapper allows format/version/exported_at/map/notice; Wanderer wrapper allows version/exported_at/map/systems/connections/signatures/kairo_notice. Omitted optional collections mean empty; supplied null/wrong shapes reject. A nonblank bounded name is required; a supplied name override must itself be valid, never truthy-fallback to another name. An empty valid diagram is permitted and is not a request to clear any existing map.

Use explicit shared portable field tables in writer and reader, not spread of a runtime projection. Native content is name/description/scope, active and archived cards, connections, signatures, observations/comments/passages and optional version1 operational_records. The existing source helpers `node`, `observation`, `comment`, `passage`, `prepareImport` and Operations `portableFields` identify the content fields; their type/length/range checks become one strict portable schema rather than relying on coercing mutation helpers. Declare recognized **export-only descriptive metadata** separately: current map IDs/kind/revision/scope_version/timestamps/read_only/track_passages, card prune/disconnection times, projected link active/confirmed/access/list/type/mass summaries, signature missing/imported timestamps, observation expired/timer_elapsed, plus bounded pings/activity, archived_connections used only to classify dead references, and wrapper notices. Validate their known shapes/limits, show intentional exclusions, and never adopt them as destination authority. Enumerate the exact finite allowlist from these assessed exporter owners during implementation review; this is not permission for arbitrary keys or an open metadata object. Source IDs used for references have the separate rules below. Selected exports omit pings/activity and unnecessary derived fields; supported current exporter metadata remains recognized, not misclassified as a command injection. No prior-version compatibility layer is required.

Reject unknown wrapper/content/record keys, including receipts/tokens/credentials/config/telemetry/delivery/cooldown state. Validate even fields/rows destined for declared omission; malformed excluded content cannot hide overflow or contradictory identities. Native operational_records allows only version/intel/alerts/upgrades and exact `portableFields` per kind; source/import timestamps are descriptive, not authority. Wanderer map allows name/slug/description; systems allow solar_system_id/position/name/custom_name/description/labels/status/tag/temporary_name/locked; connections allow source/target/type/mass_status/time_status/ship_size_type/wormhole_type plus recognized nonauthoritative locked; signatures allow solar_system_id/eve_id/name/temporary_name/description/kind/group/type/custom_info. Unknown extensions reject with bounded paths, never execute HTML/scripts or resolve URLs.

Numbers must be finite, IDs positive safe integers, enums exact and booleans Boolean; no numeric-string/Boolean coercion, fractional IDs or overflow. Keep current supported coordinates±100,000 rounded explicitly to two decimals; text trim and signature-code uppercase are visible normalization. Keep source ceilings (name80, description/body4,000, notes2,000, tags20×40, aliases100, labels120; G4/G5 field ceilings apply). Do not silently slice tags/custom_info/notes or omit invalid fields. Wanderer labels may be an array of strings, a JSON-encoded string array, or a plain non-JSON label string; malformed JSON-looking labels reject. status/type/condition/size numbers must be supported enums; unsupported supercapital export cannot masquerade as unknown. custom_info is bounded JSON/string converted to explicitly unverified note text only when the complete combined note fits; otherwise reject, never clip. Raw-field, nesting, collection and generated-text bounds apply before normalization.

Require exact valid RFC3339 instants with timezone, valid calendar dates and finite representable range; normalize to UTC without Date.parse's calendar repair or implicit missing-timezone semantics. Date fields have explicit optional/null policy: unknown observed/last-seen/expiry may be null, required historical instants may not. Preserve supplied source ages and chronology (`first_seen≤last_seen` when known, created≤updated, observed<expiry for dated intel, alert expiry equals parent expiry, acknowledgment not before alert creation); planned timer/expiry may be future, observation/creation/ack may not exceed the declared clock tolerance. Missing observation ages stay unknown; destination creation/import time is separate, not a fabricated scan.

Every input must independently fit: raw HTTP envelope≤4,100,000 bytes; raw UTF-8 document string (including whitespace)≤4,000,000 bytes; object/canonical-document serialization≤4,000,000; raw collection limits before filtering/dedup; resulting map and every child/aggregate capacity. Escaped JSON, multibyte text, pretty printing and name/envelope fields count. The object form's domain measure is its serialized JSON bytes, never a claimed original file size. The browser must check the **actual serialized request bytes**, not only File.size or textarea length. No cap increase, chunking, prefix acceptance or “every4MB file fits” promise. Detect invalid UTF-8, duplicate JSON keys, excessive nesting, huge numeric exponents and object-only non-JSON/cyclic values with bounded failures. Domain helpers must reject nonfinite values before stringify can turn them into null. A transport parse/storage failure is not a valid:false empty-map disposition.

Keep600 active cards,1,000 connections/signatures/passages/observations,500 comments,500 intel/250 alerts/1,000 upgrades and24 destination maps as observed ceilings.
