## Selected identity, admission and bounded authority

Use strict versioned envelopes, exact methods/single decoded map segment, fresh command token, runtime epoch/storage lineage, exact positive pilot/current connection and immutable payload. Reject unknown fields, conflicting pilot/scope selectors, wrong types, lossy coercion, unsafe IDs and client-supplied generated IDs/receipts. Recheck captured connection, runtime/dataset admission, catalog dependencies, map incarnation and bases after body receipt and inside commit; A→B→A is replacement. Manual local Maps work requires the connected owner but no EVE location/fleet scope. Optional collection-off does not disable local notebooks. Source/baseline adoption independently requires current source/location eligibility; module/dataset retirement fences obsolete runtime work. Guest0 remains read-only; retained exact metadata inspection after disconnect does not authorize disconnected editing.

Select one persisted **interactive-map membership revision/latest receipt per pilot**, with a stable virtual initial base and no GET write. Create/duplicate CAS that base and check24-map quota inside the final transaction. Delete CASes the exact live map incarnation/revision, then advances membership from its current value in that transaction; it need not conflict solely because another map was created. No absent-map DELETE success is selected: missing/retired target returns a nonmutating missing-target disposition, never proof of a prior deletion. All future import/create/delete writers must participate in membership authority. Automatic source creation/maintenance does not consume the24 slots or advance interactive membership. Other pilots remain independent.

Each interactive map has a nonreused server-owned incarnation and persisted revision/latest safe receipt, bound to lineage and its birth membership transition. A source map instead receives a separately minted nonreused incarnation, persisted atomically with source creation under its source owner, without advancing interactive membership or inventing a user receipt. Its deterministic `tracking-source-<pilot>` locator is not that incarnation: recreation under the same locator must reject old donor/duplicate dependencies. Detailed source tracking implementation remains successor scope. Existing integer revisions alone are insufficient across reset/recreation. Automatic map changes advance relevant authority and explicitly supersede attributable receipt evidence without inventing a user token. Manual external writers must associate their exact outer command token/base/result with touched map/child authorities. Runtime restart preserves identity/receipts; fresh profile changes lineage. No permanent tombstones, per-click journal or global unbounded history.

Child authority stays as accepted: G3's three manual lanes are **not** advanced by automatic intel traffic; G4's live/trash collection and G5's upgrade collection include their external writers. For coherent duplicate input, select a separate bounded persisted per-scope **content generation** advanced by all copied intel/alert changes, including automatic intake, ack, retention and deletion. It is a snapshot dependency, not a G3 command base. Duplicate captures source map revision/incarnation, canonical-link dependency and child signature/upgrade bases plus that content generation. Read these together; reject changed dependencies before any destination write. Canonical changes relevant to copied content must advance a source dependency even when a diagram's layout revision stays equal. Preserve G3 lane independence. Detailed external-writer implementation remains a prerequisite, not accepted selector behavior.

Tokens bind action, owner/lineage, immutable validated intent and required bases. Receipts contain exact base/result revisions, source/destination incarnation where relevant, disposition and bounded numeric counts/dependency metadata; no copied names, notes, reports, private-content digests or full topology. Same current token cannot create another map, including changed input; shared conflict/readback rules apply. Later membership changes may erase deletion/create attribution; surviving matching live-map birth/receipt evidence can still prove creation. Return partial attribution honestly when one receipt has been superseded. Bare equality, names, timestamps, map absence or matching counts never prove the earlier command.

## Create and duplicate outcomes

Require a nonempty chosen connected roster, bound to its connection identities; owner is not silently reinserted when deselected. Capture local catalog, explicit-bloc/complete-sovereignty evidence and eligible source/baseline identities. Do not fetch providers, scan history or create donor maps as an incidental read. Missing donor means no available evidence, not a fabricated empty scan. New local map creation remains possible with no eligible location/source evidence.

Source creation retains the current distinction: scoped maps adopt matching components from chosen pilots; unrestricted adoption requires the explicit source option. Capture a finite coherent local donor snapshot at admission, with bounded source incarnation/revision/generation references, then recheck before commit. Invalid source locator/kind/ownership rejects. Expired/ineligible donors cannot acquire fresh lifetime or route authority. Preserve original observation/expiry, new owned link identities, unconfirmed/inaccessible state and no private notebook/config/Places copying. A baseline may add its eligible current wormhole system, with no inferred passage from old continuity.

Select whole-component population with deterministic donor/component order. A component that cannot fit is skipped entirely, coverage unconsumed; expire-before-copy components are explicitly omitted, not orphan cards. Commit the valid map and fitting components together, reporting `complete` or `partial` population with bounded copied/skipped counts and reasons, including none-available. No unbounded per-component receipt history. Full input/transaction failure still rejects all creation; partial population is a domain result, not a swallowed storage/validation error. No automatic retry of skipped components by command reconciliation; later normal tracking has its separately pending contract.

Duplicate may read either an owned interactive map or owned live source into a **new editable map**; source remains read-only and unchanged. Preserve source scope, descriptions/layout/annotations, eligible historical observations/comments/passages, live signatures and intel/alerts/upgrades with fresh destination identities and remapped exact references. Preserve original observation/expiry and acknowledgment provenance; signature copies remain missing until newly observed. Retain no source trash, undo, command receipts, delivery evidence, cooldown authority, live roster/location/fleet/config, source coverage, pings or navigation plan. Add owner-only tracking with a fresh eligible baseline; passage recording defaults off, as current import does. A copied historical alert never triggers a semantic alert/event, sound or desktop notification.

New owned wormhole/link copies are unconfirmed/inaccessible; expired/collapsed links and dependent edge-only records are omitted explicitly, never renewed. Exact configured global Ansiblex identity may remain a shared reference only if the same eligible configuration/endpoints still exist at commit; copying it neither changes its access nor makes it map-owned. Static gates retain catalog identity. Report copied/omitted counts by bounded category; unavailable catalog identity or malformed internal references reject rather than silently reinterpret/drop unrelated retained notes. Historical archived cards remain distinct from current topology. The full duplicate must fit all destination map/child limits: overcapacity rejects atomically, with no partial duplicate, silent trimming, chunked copy or increased ingress limit. A local duplicate need not serialize a portable document or roundtrip through the HTTP import body. This selects lifecycle copy semantics without accepting088/089 portability.

## Atomic retirement and follow-up

Delete expresses whole-map retirement, including child records present at its commit; it requires the observed map incarnation/revision, not every child command lane/content base. Thus independent G3 traffic does not invalidate its own lane merely to service deletion. In one short local transaction, check the live map, remove its owned canonical links and exact bound observations, all scoped live/trash signatures, intel/alerts/upgrades and their authority/receipts/cooldown/delivery associations, scoped navigation state, map/undo and authoritative roster, then advance membership with the exact deletion receipt. Child writes racing retirement either commit before it and are removed, or reject the retired incarnation; delayed work/undo may never recreate the scope. No reused ID can revive an old child base. Receipt inspection returns unavailable child evidence once retired; only surviving parent membership evidence can attribute the deletion.

Cleanup is ownership-directed: remove only this pilot/map's owned links/records; retain shared configured Ansiblex, other maps/pilots, global Operations records, installation-wide Places annotations, global metadata and historical semantic events. Remove or invalidate other retained derived references to the retired links in the same authoritative boundary; never leave a route executable through a dead link. Navigation algorithm/waypoint behavior remains pending. Do not execute legacy Places transfer/delete as lifecycle cleanup; F2 already selects its retirement under the clean-slate policy.

Every required map/link/child/revision/receipt/quota change commits together; any required failure rolls back all. No provider/filesystem await inside the transaction. Expiry maintenance is a separately attributable owner transition, not hidden partial success of a rejected lifecycle command; reconcile or classify due evidence before capturing final bases, or include required cleanup in the outer transaction. Clock-derived exclusions cannot renew ages. Defer callbacks, expiry scheduling, tracking-index publication and notifications until **actual outer commit**, not helper savepoint release. Stage runtime index changes or rebuild from committed rows after rollback/restart. Fence retired map authority synchronously before fallible publication; no obsolete subscription can deliver into it after successful retirement.

Return exact committed identity/revision/receipt and population/copy/deletion disposition separately from tracking application, invalidation and optional current projection. A failed projection/SSE/callback cannot reclassify the local commit or authorize replay. No lifecycle semantic timeline event is required merely for attribution; existing map activity is local content. Bounded index reconciliation applies current committed truth without replaying old commands/toasts. Closing browser/dialog or switching pilot detaches its observer, not admitted work. Shutdown/dataset handoff closes admission, drains owned transactions and actual tracking/callback occupancy before Store close; deadline exhaustion is an unresolved/failed handoff, not assumed rollback.

Delete does not change the active-tracking **pilot** pointer or unrelated explicit subscriptions. Source deletion is rejected; source duplication does not switch the recorder. Only the still-owning browser may select its newly created map or clear its deleted selection. Cross-tab removal invalidates a matching selected incarnation/route context; it cannot retarget another map or erase unrelated drafts. HTTP083 and browser-local storage semantics require their own acceptance.
