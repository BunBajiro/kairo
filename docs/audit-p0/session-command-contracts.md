The normal single runtime executes each synchronous service call without JavaScript interleaving; that is not a persisted compare-and-swap contract. Current End addresses whichever Session is active when it executes. Current details saves from other tabs/process lifetimes can overwrite each other; the module queue only orders one dashboard lifetime.

Request disconnect/navigation does not undo an executed statement. Server shutdown tracks and drains admitted handler promises before closing stores; this does not establish bounded completion of every dependency or browser acknowledgement. Existing `GET /api/sessions` gives paginated summaries and `GET /api/sessions/:id` gives an owned report, but neither supplies command identity/revision. Report GET also computes domain projections and can schedule combat sync; it is not a cheap side-effect-free command receipt lookup. No lost-acknowledgement reconciliation is implemented here.

## Selected target contract — requires implementation and acceptance

### Identity, validation and ordering

Use the [shared P0-02A command envelope](command-contracts.md): a fresh command token for each explicit accepted intent, an expected opaque entity revision and storage-lineage identity. Tokens/revisions are server-validated and scoped to the authenticated local profile and entity; stale pre-reset references cannot match a fresh profile. Do not add an unbounded historical receipt log. The current entity stores its revision, last committed token and exact result together with its state. Wire spelling and measured metadata limits follow the shared contract; the domain fields below are fixed requirements.

| Entity / intent | Required intent fields and checks | Compare-and-swap / exact committed result |
| --- | --- | --- |
| Pilot Session lifecycle — Start | Captured connected pilot; `action: "start"`; expected lifecycle revision and no active Session. Optional string `label`: omission retains the existing `Flight session` default; supplied name must trim nonblank and fit 100 code units. Reject wrong types/oversize values rather than silently coerce/truncate. UI continues requiring its entered name. | Under one commit boundary revalidate ownership/precondition, allocate Session ID, capture boundary once, insert Session and semantic event, advance lifecycle revision/token. Return that exact command's ID, start boundary, normalized label and resulting lifecycle revision/token; do not reread later state to compose an ack. |
| Pilot Session lifecycle — End | Captured pilot; `action: "end"`; **explicit `sessionId`** and expected lifecycle revision. Target must still be that pilot's active Session. No end-label field is accepted. | Atomically end that exact Session and store its end boundary/context, semantic event and next lifecycle revision/token. A stale End cannot end a replacement Session. Ack identifies the ended Session and exact committed end boundary/revision/token. |
| Session details — Save | Captured pilot and exact Session ID; both `label` and `notes` required strings. Trim name only; name nonblank and at most 100 code units; notes at most 12,000 code units. Empty notes intentionally clears; omission is invalid. Reject oversized text without truncation, preserving the editable draft. | Compare that Session's **details** revision; atomically update only name/notes and details revision/token, returning those exact normalized committed values. Ending a Session or new combat/report evidence does not itself conflict with details edits. No semantic start/end event is generated. |

Validate complete body shape, action-specific keys and ownership again at the commit boundary, after all awaits. No command rejection may perform loyalty reconciliation or another hidden write. Protect the one-active-Session invariant in durable storage as well as service validation. Preserve Unicode text without splitting scalar values; matching UI/server validation and storage limits need acceptance tests. Do not use wall-clock/client timestamps or mutable UI resource counters as concurrency revisions.

CAS decides conflicts across tabs and after runtime restart. Every new successful save advances its entity revision, including a save of equal values. Conflicts leave durable state untouched and return structured current entity identity/revision with enough safe state for review. Preserve the submitted and any newer local draft; a replacement is a fresh explicit intent after reading current state, not an automatic last-writer-wins retry. A same-dashboard accepted details queue may use the proven predecessor revision for a later save only while retaining that save's own immutable values and lineage. If the predecessor is rejected, conflicts or becomes uncertain, pause dependent writes; do not automatically release them using an assumed revision. P0-04 must bound admission, wait and retained drafts before implementation.

### Acceptance, commit, publication and acknowledgment

1. **Local acceptance:** capture entity, normalized immutable intent, base revision and command token before queuing. Navigation retires view-specific feedback, not accepted intent. Pre-dispatch cancellation can withdraw a queued intent only with a definite never-dispatched result; do not silently drop it or claim rollback.
2. **Server admission:** authenticate and validate shape/size first. Check connected-pilot ownership and command preconditions again inside the synchronous commit boundary. Rejections before commit are definite only when the structured result explicitly establishes that outcome for this token; generic transport/status/JSON errors remain uncertain.
3. **Atomic commit:** persist entity mutation, required Session history event, revision, token and exact result in one transaction. Required loyalty accounting for Start must either join that transaction after validation or have a separately proved idempotent projection owner; a rejected Start cannot change older Sessions. SQLite failure rolls the entire required unit back. Do not acknowledge committed before this boundary completes.
4. **Postcommit delivery:** bus listeners, SSE revisions, bindings and combat refresh do not change the recorded mutation outcome. Failures keep the committed result available and belong to the failing owner. Required derived gameplay accounting must recover through idempotent work or projection rebuild, proved per dependent owner in P1/P2; do not assume every bus subscriber is transactional. Transient application/Stream notifications must not automatically replay on restart/reconnect. Stream toasts remain excluded from app-toast consolidation.
5. **Client acknowledgment:** validate response schema, entity/lineage/token and exact resulting revision/state. Apply only to the captured command owner, preserving any newer editor draft. Failed list/report refresh cannot turn a confirmed commit into a failed save. User feedback must describe confirmed commit, conflict or uncertainty; diagnostic/toast details are P0-03/P4 work.

### Unknown outcomes, cancellation and restart

| Situation | Selected behavior |
| --- | --- |
| Timeout, abort, malformed/mismatched ack or disconnect after dispatch | Treat outcome as unknown. Issue **one initial lightweight authoritative read** of that entity's revision/last token/exact result; no full report polling, no automatic mutation resend. A matching entity, lineage, command token and bound base/result revisions proves commit and recovers the exact result. |
| Last token missing/different, entity superseded or read unavailable | This does **not** prove noncommit. Preserve uncertainty and drafts; offer an explicit later read/current-state review, not a retry loop. A fresh deliberate intent requires current state and revision. A Start/End must never be inferred successful solely from a same-named or apparently active/ended Session. |
| Repeated current token or stale base revision | Reject with conflict/readback disposition and no additional mutation or semantic event. No idempotent mutation replay is selected. After token supersession there is no permanent replay-history guarantee; the client must never reuse an old token, including against a fresh revision. |
| View closes/pilot changes | Retire its feedback and detach view waiting. Preserve captured accepted ownership; do not redirect a Session write or acknowledgment to the newly selected pilot. Aborting transport is not command rollback. |
| Runtime restarts with same profile | Durable revision/token/result survive; lightweight readback can resolve the outstanding command if still current. Publication/collector repair must respect provider cooldowns, module state and shutdown ownership. |
| Browser closes/restarts | No automatic write replay or persisted secret/draft journal is selected in this unit. If the browser no longer has its command token, it can read current state but cannot reconstruct proof of a historical acknowledgement. Reopening must read authoritative state before accepting a new command. Any later decision to persist pending command metadata requires bounded/redacted storage and clear lifecycle acceptance; do not imply it is implemented. |
| Fresh profile reset | New storage lineage invalidates old entity references. Report unavailable old identity; do not recreate old commands, preserve a legacy migration path or infer prior noncommit. |

The new lightweight readback must return only owned command state: lifecycle's current active ID/revision plus last committed transition result; details' current name/notes/revision plus last committed details result. It must not run Session report computations, schedule combat collection, expose another pilot, mutate state or replace local drafts. Exact endpoint placement is shared-contract implementation detail; required cost/read behavior is fixed here.
