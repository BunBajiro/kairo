## Selected target: a finite admission action

Manual Sync remains an **admission-only command**, not a new full-refresh job. Its result records a finite scheduling decision; downstream owners retain their own observation, error, accounting and output outcomes. Unlike a durable preference save, this action has no local-commit CAS receipt or replay journal. The shared rules for immutable intent, exact attribution, unknown outcomes, no blind resubmission, view ownership and capacity still apply.

| Boundary | Selected behavior for implementation |
| --- | --- |
| Input / identity | Require a complete strict object with a fresh opaque command token, caller-known runtime epoch and storage lineage, and explicit character `0` or a positive safe integer. A nonzero target supplies its expected connection revision. Bootstrap exposes all required epoch/lineage/current connection preconditions before POST. Reject missing/extra/invalid fields, stale runtime/lineage and replaced/absent selected pilots before effects. A current repeated token only reads/conflicts; it cannot admit another scheduling action with changed payload. |

Record disabled/missing-scope/reauth/inapplicable branches as dispositions; never turn them into empty success. Later module enablement, pilot selection or protection-owner changes do not enlarge or retarget this accepted scope. |

The selected coalescing policy deliberately avoids a per-click follow-up run: useful current work may satisfy a click. A source already passed in an ongoing pilot run may receive its single bounded demand for a later eligible pass; it cannot acquire a second marker from repeated clicks. Protection-only sources for another pilot retain ordinary due/cache policy: capture admits a finite current protection opportunity, not forced polling cadence or access-failure clearing for that pilot. A source overlapping selected-pilot/shared work may use that work's manual demand. Disabled sources receive no dormant manual intent that silently activates after a later enable. Disabling a source after admission likewise retires its unstarted manual demand; a later enable does not restore that demand. This does not discard a still-valid already-dispatched off/on response or accepted accounting. Automatic polling and independent protection progress continue under their existing owners. This is a thin manual-command admission owner over the existing scheduler: internal Auth/Markets refresh triggers and routine ticks do not allocate browser command tokens or manual status records, and do not become a second collector system.

## Read-back, UI and replacement

Keep only the latest safe manual admission record per live selected pilot plus the shared target, with finite runtime-wide count/byte/retention limits. Do not retain deleted-pilot tombstones or a token history. The record binds the command token to immutable validated input, runtime/lineage, target/connection and captured component decisions; bare token equality or matching snapshots is insufficient. A later record can supersede attribution for an earlier click.

Select a private provider-free **GET `/api/sync`** status read, with an optional exact target/token selector validated under the same private session. Return the current epoch, matching admission evidence if retained, and bounded current demand/owner status separately labelled as present state. It must not call `requestSync`, `access`, protection collection, Combat, Registry hooks or providers. Register this new read in the HTTP manifest during implementation. The admission action is complete once its scheduling decision is recorded; a queued marker or active collector is not a promise of eventual all-source success.

After a lost/unreadable response, make one initial passive reconciliation read; then allow deliberate inspection. Unknown token, expired/overwritten record, missing pilot or changed runtime means unavailable attribution, never proof of rejection. Browser/runtime loss does not replay a saved sync payload. Dataset replacement creates a new runtime epoch: the new child may resume ordinary scheduling from durable samples and provider deadlines, but does not recreate the old manual command or claim its outcome.

The dashboard snapshots selected owner and response generation, preserves newer navigation, and releases its request busy state on a bounded acknowledgment/read outcome. A late response cannot clear a newer request's state or refresh/publish into another pilot's view. Keep “requested” feedback distinct from snapshot-load failure and collection freshness; use the forthcoming P0-03 application-toast owner without adding a second renderer. Existing SSE/reconnect/state ownership handles ordinary convergence; no per-component polling loop or forced state refresh creates provider traffic.

Browser abort/unmount detaches its observer and does not undo accepted admission. Runtime quiescence stops automatic producers and new command admission; owned collection and accepted accounting retain dependencies through drain. Expire unstarted manual demand under the shutdown owner, preserve valid committed samples and report interrupted/unavailable attribution honestly. A missed deadline or forced child exit is a failed handoff, not successful completion. Dataset generation activation remains in its separate contract.
