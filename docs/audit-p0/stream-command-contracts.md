## Selected configuration and preview contract

| One complete saved entity | Treat the full Stream configuration as one CAS entity. Validate an immutable full accepted snapshot, its base revision and shared command metadata. A stale save conflicts without overwriting unrelated newer layout/rule edits or affecting timers/bindings/output. No implicit field merge. Same-value commits follow the shared revision rule without requiring unnecessary public DOM changes. |
| Strict canonical input | Reject unknown fields, wrong types, nonfinite/out-of-range numbers, overlong strings, unknown enums, invalid/duplicate element IDs and duplicate/unknown rule events before mutation. Save requires one explicit canonical rule per supported event; omission cannot silently delete or reset a rule. Never assign a replacement ID, truncate text, clamp a supplied number or select the first duplicate during acceptance. The editor generates unique IDs and materializes documented defaults before its accepted snapshot; server-returned canonical configuration must preserve that snapshot's meaning. |
| Existing legitimate semantics | Keep the supported kinds/bindings/positions, present numeric ranges and 50-element limit as current compatibility controls pending P0-04 measurement. Do not add a wholly-inside-canvas rule: current independent geometry limits permit deliberate partial placement. Preserve zero/past countdowns, fractional valid geometry, static copy, template placeholders, sample tests and automatic-rule defaults. Optional fields may materialize explicit documented defaults; missing element pilot remains follow-default, zero remains local, and positive IDs remain exact. Editor blank template controls must resolve their documented reset-to-template meaning visibly **before** accepting a save; the server must not silently replace a submitted canonical title/message. |
| Binding/reference validity | Validate the binding-kind combination and dependent field shapes, including opaque full-opacity protection elements and zero countdown deadline on non-countdown kinds. Reject unsupported combinations instead of clearing them silently. A saved reference whose source/pilot is temporarily unavailable remains that exact reference with unavailable output; never substitute another pilot or discard valid layout intent. Runtime-only projection fields are not private save inputs. |
| Atomic commit | Prepare bounded local candidate projections only after strict validation, then recheck authoritative ownership/CAS if preparation ever awaits. Atomically persist configuration, new revision and bound receipt tuple. Failed transaction leaves previous config, bindings, timers, cooldowns and output authority unchanged. No test notification or provider work is part of saving. Capture the exact committed canonical result/revision before follow-up. |
| Commit versus output | Immediately install the minimal current-config/output fence below before fallible serialization/publication. Apply current committed pause/rule restrictions and affected binding eligibility even if broader projection/history work fails. A postcommit failure returns attributable saved intent plus failed/pending convergence, never an invitation to resend. | Passive configuration read | Extend private GET `/api/stream` with canonical config, durable revision/latest bound receipt and separately labelled current output generation/convergence disposition. The editor keeps accepted snapshots, newer dirty drafts and last saved canonical state distinct. Follow the shared confirmed-predecessor rule for the dashboard queue; conflict/unknown pauses successors instead of silently rebasing over another tab. Navigation, abort and remount cannot undo accepted saves or clear another editor generation. Fresh runtime startup reads the active profile's config/revision/receipt and begins without release authority until current projection; browser restart reads current truth without replaying lost payloads. No legacy-profile migration gate is introduced.

## Shared output authority and bounded client freshness

Core owns protection/source authority; Stream owns projection, notification scheduling and public delivery. The authority identity is distinct from the durable config revision, OPSEC category and notification identity. At a successful relevant commit or authoritative source/access change, establish a minimal nonthrowing synchronous fence **before** fallible projection, semantic event insertion, ordinary broadcast or OBS notification. Failed persistence leaves the old committed command in force. If the process dies after commit, startup is covered before exposing release-capable output.

- Saved pause/rule restrictions, protection, Auth disconnect/needs-reauth, relevant module disable and protected/default-pilot changes invalidate affected cached binding/output authority immediately. Same-category changes still count. Default-pilot changes cannot retain old implicit-pilot values; unaffected explicit bindings retain their valid cached work. Fencing must not require full-history/provider reads or broad repeated projection.
- `state()`, pending toast delivery, `outputToast()`, public response serialization, initial SSE state and queued frames all consult the same current owner/generation. A restrictive update must retire stale queued release/private-value frames or disconnect the affected writer through bounded cleanup; it cannot sit behind them. When full projection fails, serialize the minimal safe current state rather than old-owner values. OBS revocation and safe dispatch are independently owned as specified by the [OPSEC fence](opsec-command-contracts.md#protection-and-output-fence); a semantic event failure cannot skip them.
- Accepted semantic notifications are not identical to live bindings. A module disable does not automatically cancel every already accepted domain observation. Keep accepted-domain ownership/accounting and the existing rule/filter/pause disposition explicit; current wording/location/protection still gates delivery. Reconstructing current state or repairing descriptive history must not replay transient Stream toasts. Reconnect may show only still-current, unexpired retained notifications using original times.
- `writeSSE`, a completed HTTP response and a configured OBS action cannot retract already transmitted bytes or prove physical pixels/audio. Disconnected or expired clients use only cover geometry already received/safely cached; a fresh source cannot invent an OBS layout. These limits remain visible in the product guidance and acceptance claims.

**Select a receiver-initiated passive authority proof**, because an old queued SSE frame cannot safely renew a lease merely by arriving recently. Add public GET `/authority` alongside `/state` and `/events`; it is a new read dependency, not an existing manifest route or mutation acknowledgment. It returns only bounded public metadata: echoed strictly validated nonce, public runtime identity, output authority generation, current public state revision, scoped projection validity and conservative eligibility lifetimes. A binding's unavailable/error state cannot withhold the common proof or an independently valid cover-release grant. The read and response are explicitly noncacheable; a cached/304 response cannot renew authority. It exposes no private receipt/pilot/source IDs, performs no projection/provider/semantic-event work and retains no per-renderer receipt history. Admission and response bytes are bounded.

Validate each complete public state/toast/proof DTO before installing or caching it: supported shape, bounded counts/bytes/text, unique public element IDs, finite geometry/timing, enums and exact runtime/generation/revision/nonce types. Malformed data grants no authority, installs no partial layout and cannot renew proof; conservatively clamp current known output where needed. Do not trust a parsed JSON object as a validated snapshot.

Each renderer owns at most one outstanding probe, shared by all its widgets. Record its local **monotonic request-start** time and fresh nonce; accept only the matching response before its bounded request deadline. Each granted lease ends no later than request start plus the smaller of the configured maximum lease and returned remaining eligibility lifetime, never response arrival plus a new lifetime. A validated state may obtain authority only under the same public runtime/generation and at least the probe's minimum state revision. Within a runtime, reject revision regressions; an equal idempotent snapshot can be accepted without DOM change, audio replay or lease renewal. Reconnect invalidates old probe/handler ownership through a connection generation but permits the unchanged authoritative snapshot to establish the new connection's baseline under fresh proof. Only a fresh nonce proof establishes a changed runtime identity.

Presentation/data-only newer states in the same generation may reuse already granted scopes for their remaining lease without renewing it. Ownership, privacy, release eligibility, cover configuration, pause or binding-eligibility changes must advance the authority generation, including a replacement observation with an earlier expiry. A new live binding requires a proved scope. This avoids harmless-update starvation while rejecting stale queued first/next states as fresh authority. A validated restriction may clamp current known output/geometry immediately; it cannot install stale/unknown-runtime layout or replace newer cover geometry merely because its `hidden` flag is true. Installing state still obeys runtime/revision validation; a different release-capable generation waits for current proof. SSE state, toast frames, socket-open and comment heartbeats cannot independently grant or renew a lease. Server changes not yet observed by a client remain bounded by the existing lease; this is not instant remote revocation.

One proof supplies a common transport/ownership lease, a cover-release lifetime only when protection legitimately permits release, and live-binding lifetimes keyed by the existing public element IDs. The map is bounded by saved visible bindings (currently at most 50); identical internal scopes may share calculation. **Protected OPSEC still permits legitimate widgets/toasts.** An already unavailable binding needs no live-value grant and cannot zero unrelated leases. Cover-release expiry restores known covers without discarding otherwise valid widgets; a binding expiry makes only that binding unavailable. All scopes depend on the common proof: common-lease expiry restores known covers **and** clears transient output/live bound values even if a scoped deadline remains. Each toast keeps its own earlier original expiry. This adds bounded metadata, not a second full snapshot or per-widget renewal loop; P0-04 measures the byte/cost tradeoff.

Missing, malformed, timed-out or saturated renewal grants or extends nothing; an existing still-valid proof may run only to its original deadline. Every state/toast/render path checks applicable expiry **before** a reveal, including when an expiry timer runs late. The same one-owner protocol covers `/stream`, `/stream/toasts`, `/stream/opsec` and `/stream/widget/{id}`. A renderer with only static/protected layout and no revocable live content, transient output or cover-release need does not continuously probe just to retain that layout; a new eligible frame or activation/resume can trigger its shared proof. Public `/state` also materializes current eligibility/protection safely independent of renderer compliance. Existing static approved wording can remain; absent/deleted/invisible covers and arbitrary OBS mappings never imply full-frame concealment.

The server's remaining duration for each scope comes from its **nonextendable monotonic eligibility deadline**, using the earliest required evidence for that scope. Anchor evidence lifetimes to accepted observation identity; repeated projection, cached metadata, probes and heartbeats cannot reset them. A genuinely new accepted sample may support a later new probe, never extend an installed lease through SSE arrival. Clock anomalies expire/revalidate conservatively; recomputing `validUntil - Date.now()` must not extend an old observation after a wall-clock rollback. Renderer reconnect/runtime identity change discards the prior proof and renews from current truth. Sleep/resume or a detected wall/monotonic timing discontinuity invalidates authority before normal rendering resumes; P0-04 and browser acceptance must establish the supported monotonic/suspension behavior. This is a bound while renderer code executes, not a promise to erase frozen pixels during browser/OS suspension. No renderer acknowledgment history or repeated full-state polling is selected. Numerical lease, probe, aggregate-client and failure budgets belong to P0-04 before implementation.

Protocol references checked 22 October 2026: the WHATWG [event-stream interpretation](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation) ignores comments and queues dispatch tasks, with [buffering caveats](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream); [HTML timers](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timers) do not guarantee exact execution times. The W3C [High Resolution Time working draft](https://www.w3.org/TR/2026/WD-hr-time-3-20260901/#clocks) distinguishes monotonic from wall clocks and [clock drift](https://www.w3.org/TR/2026/WD-hr-time-3-20260901/#clock-drift). These support constrained design assumptions, not measured engine/suspension or physical-output guarantees; P0-04 and Chrome/Firefox acceptance remain required.

## Explicit test emission contract

Test is a separate transient output command, not a save or a provider mutation. Validate a strict object with a known event, **expected saved configuration revision**, current public runtime identity and fresh command token. Reject stale config, invalid event, paused/closed owner or excess capacity before admission; preserve the unsaved editor draft and identify the saved revision actually tested. No fallback from malformed/missing event to a different event. Tests use schema samples and intentionally bypass automatic enabled/pilot/cooldown filters. Give synthetic tests a separate bounded admission budget; they must not consume or reset real automatic-event cooldowns.

Reserve a bounded operation-status entry and notification/timer ownership before admission. The exact acknowledgment identifies this command, saved revision, notification ID and original scheduled/expiry times; it means **scheduled/admitted**, never delivered/displayed/heard. Admission does not advance the saved config revision. A repeated currently retained command token cannot schedule again; changed intent with that token rejects. There is no permanent replay-history promise after bounded evidence disappears, so the client never reuses tokens or automatically retries an uncertain POST.

Preserve accepted original delay/duration while using current wording, sound/mute, location permission and protection at delivery. Anchor accepted scheduling/expiry to monotonic ownership; wall-clock rollback, duplicate state and reconnect cannot extend a notification's original lifetime. Automatic-rule disable or pilot-filter edits do not invalidate a sample test; pause, shutdown or explicit queue eviction retires it. Resuming does not replay cancelled work. The current bounded transient display may evict older entries; distinguish that outcome from admission rejection while evidence survives. Never restore pending test timers after runtime restart.

Select a private passive status read, **GET `/api/stream/tests/{commandToken}`**, bound to the originating runtime identity. Stream owns one bounded in-memory status set, reporting `scheduled`, `dispatch-attempted`, `cancelled`, `evicted` or `expired` with original identity/timing and safe reason. Dispatch-attempted includes zero connected renderers and proves no receipt or actual output. The status read performs no emission, projection or provider work. A lost/malformed acknowledgment gets one initial bounded status read, then deliberate inspection if unresolved. Absent/expired status or a restarted runtime means **unknown earlier outcome**, not rejection; no automatic replay. A later explicit click is new intent against observed saved state, not reconciliation by resubmission.

Bound status count/bytes/lifetime, rate admission, retained notification/event payload bytes, timers and queued UI intents together in P0-04. Reserve capacity before acceptance; cap rejection leaves the new intent unaccepted. Terminal status may expire under that declared bounded policy; never pretend its loss proves the command did nothing. Page changes/aborted requests do not cancel an admitted test; owner pause/shutdown cancels scheduled work and retains truthful status while possible. Drain releases timers/listeners and fails explicitly if owned work cannot settle within its budget.
