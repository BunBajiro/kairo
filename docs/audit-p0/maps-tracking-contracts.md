## Selected global authority and input

Keep one persisted global selection entity, with storage lineage, nonreused revision and **one latest safe command receipt**. Its absent virtual base represents explicit default **0/none**, stable for that lineage/schema, without a read write. Select no dynamic first-account fallback: until a deliberate selection commits, source recording is idle. Initial/remounted/stale tabs, CSRF refresh, roster reorder/removal and localStorage restoration never seize this pointer. A deliberate pilot-picker change selects that pilot for recording. When the viewed pilot is not confirmed as the selected recorder (none/different/unresolved), the pilot control must also expose a meaningful **Use this pilot for recording** action after current inspection, so a one-pilot installation and re-selection after conflict are reachable even though the native picker cannot fire a change for its already selected option. This is a recording-state action, not an internal-repair notice. This intentionally replaces implicit bootstrap behavior and needs requirement acceptance.

083 accepts one strict versioned object: fresh opaque token, caller-known runtime epoch/storage lineage, expected global selection revision, required numeric `character_id`, and the exact target connection incarnation when positive (none for0). Reject unknown/missing fields, arrays/null, strings/Boolean IDs, negative/fractional/unsafe/nonfinite IDs, conflicting query pilot/map selectors and unsupported route/method.0 is the sole intentional clear; omitted/null/empty input is never clear. Positive targets must be currently connected at domain admission **after body receipt** and at final commit, with the same captured connection. A stale A→B→A connection is a conflict/retired owner, even if numeric ID/name match. No target switching during waits, automatic retry until connected or arbitrary fallback recorder.

Manual local selection does not require EVE location scope, a ready sample or enabled optional collection. A listed reauth-required pilot can retain selected preference but cannot record; disabling Universe/Pilot/Operations or logs never silently chooses another pilot. Admission requires current private authorization/runtime availability and bounded capacity. Once accepted, browser/socket departure does not cancel it; actual target connection/lineage/runtime retirement before commit rejects uncommitted work. Selection of0 remains available when no pilots are connected. Normal restart preserves the preference/revision/receipt; fresh profile changes lineage. A persisted selected pilot later disconnected remains selected-but-unavailable until a new explicit command; reconnect of that ID may regain eligibility under a **new** reader/continuity identity without fabricating a new user command.

Global CAS orders competing tabs at commit, not click time or localStorage timestamps. Every fresh successful command, including same-value/0→0, advances selection revision and receipt. Same-value selection with unchanged active source/connection/control continuity is a **domain no-op**: do not clear its baseline, recreate its source, replay a sample or restart readers. Same numeric pilot after relevant retirement is not continuity equality; the lifecycle below must establish a fresh generation before recording, regardless of a no-op command. Same current token is conflict/readback with zero new commit, including changed payload; never reuse superseded tokens.

Receipt binds action/lineage/token/global base/result, exact selected0-or-pilot and accepted connection identity, and bounded affected source incarnation/continuity base/result metadata plus changed/no-op/cleared disposition.
