## Selected admission and target intent

Both POST envelopes include a fresh command token plus the caller-known **runtime epoch and storage lineage**, exposed by bootstrap/GET `/api/datasets`. Reject stale/missing epoch or lineage before domain admission. An old delayed Install must not become a fresh same-build retry in a replacement runtime merely because its in-memory token association disappeared; candidate/build equality cannot override this fence.

| Request / owner | Required contract |
| --- | --- |
| Check | Strict bounded command envelope with fresh token and current runtime identity; no candidate mutation intent. Admit a metadata observation operation, or explicitly join eligible shared metadata work. Its exact result states fresh/cached/throttled/failed observation and the observed candidate/selection revision. Joining an install does not mean Check authorized that install. It need not wait for conversion/activation to finish its observation. |
| Explicit Install | The existing UI says “Build N is available”: snapshot that **server-issued candidate identity/build and selection revision** with the command token. Once accepted, freeze that target: discovering N+1 later cannot silently retarget the N job. This is a selected change from Build97's latest-at-decision behavior. |
| Automatic install | The scheduler selects current latest eligible data independently under the same owner/capacity/provider rules. It must not inherit a manual retry permission for a different target. Preserve one deadline owner, cached metadata and no per-tab/background-loop multiplier. |
| Join / escalation | Preserve one metadata/preparation flight. Equivalent target commands explicitly join its canonical job; while a metadata-only decision is still open, an admitted Install may upgrade that job's intent. Bind each response to its own token and state whether it created/joined/escalated work. Same-target joining uses candidate/job identity and must not fail merely because admission changed advisory status. Once target/installation decision closes, late requests cannot silently modify it; different targets reject busy/conflict without a hidden queue or extra download. |
| Failed-build retry | A fresh explicit Install may authorize one fresh UUID attempt of the same failed build after current eligibility/capacity checks. | Already current / mixed components | Never downgrade any official component below the validated installed/bundled floor. ## Preparation, activation and receipt state machine

Select **one bounded current pending record**, carrying immutable job/target/generation identity and the canonical safe install receipt: the token that created/escalated this frozen installation job. Its state distinguishes provisional preparation, eligible handoff and a claimed activation attempt. Later join associations remain bounded in memory and do not rewrite the pointer per caller. An automatic job has its own server-origin identity, not an invented user command. This is not a command journal or a receipt for every join. Wire/layout choices remain implementation work, but the following publication and failure semantics are required.

| Boundary | Required meaning and failure behavior |
| --- | --- |
| Accepted in this runtime | The owner has reserved one job/target and a bounded command association. HTTP 202 acknowledges that exact admission/join, not prepared or installed data. Until surviving publication exists, crash can lose this in-memory attribution; absence cannot prove rejection. |
| Provisional generation/pointer | Archive conversion and full generation validation completed; provisional pointer may be published, but **it is not eligible for supervisor activation**. Cancellation before entering final eligibility publication can retire it. Failed marker/cleanup does not promote a provisional record. Old active readers remain on their immutable directory. |
| Preparation committed: eligible | After final validation/abort fence, atomically replace that same pending document with eligible state plus exact job/generation/target/base/receipt tuple. Entry is the **cancellation cutoff**; the successful atomic replacement is the preparation commit. Close joins the actual filesystem result and reconciles an uncertain rename; it cannot certify cancellation merely because its signal fired. A successfully completed eligible preparation may activate on the next start, as the existing completed-before-close rule intends. |
| Old owner stopped | Stop admission, quiesce producers and drain accepted owners; require stopped acknowledgment and actual old child/worker exit before replacement or reclaiming their files. A timeout/kill is a failed handoff, not a successful save. An unresolved owner cannot be replaced by overlapping work. |
| Activation claimed | **After old-owner exit and establishment of runtime occupancy ownership**, under the exclusive launcher lease, durably change the same pending record to claimed before launching that UUID. Failed/unreadable claim means no launch. Restart with claimed pending and **no matching committed active tuple** does not automatically launch that UUID again, even if the crash occurred before launch; retain interrupted/unknown disposition, use independently valid active data and require a fresh UUID for a later explicit attempt. |
| Candidate internally ready | Static indexes, checked Store/Vault/resources and dormant listener binding are prepared for the exact claimed selection. This is an internal supervisor readiness signal, not user command admission, public release, extension readiness or installed success. Failure before active commit may reject the candidate and attempt one verified active/bundled fallback after actual exit. |
| Active pointer committed | Atomically publish the active generation **with its bound job/target/base/result identity and canonical receipt in the same document** after candidate internal readiness. This is the authoritative local selection commit. Matching active evidence wins over a lingering claimed/pending record. A later IPC/status/cleanup failure cannot roll it back or delete it as a failed candidate. A rejected/expired publication promise alone does not prove precommit failure: reconcile the exact active tuple before rejection, deletion or fallback. |
| Runtime activated | Parent authorizes the exact committed generation/runtime identity; child establishes the local gate/required owners once and acknowledges that readiness separately from ordinary provider convergence. Sending IPC alone proves neither gate release nor a healthy child. Duplicate activation is inert; wrong/old activation or activation after stopping rejects. Normal recoverable ESI/OBS/provider outage remains degraded owner state: it must not block activation waiting for every initial read, kill an otherwise viable runtime or roll back data. Mandatory owner initialization/import failure is separately failed/unknown activation with owned cleanup, no rollback of committed data and no blind retry of an uncertain extension hook under the Modules contract. |
| Workspace ready | UI observes matching committed generation/job evidence and successful current bootstrap/state refresh. Report activation, workspace-read failure and rollback separately. Build equality, SSE open, preparation 202, worker result or parent IPC send is not this acknowledgment. Preserve mounted drafts and current page. |

Do not imply atomicity between pending and active files. Recovery compares their exact bound tuples and declared phases: matching active commit is authoritative; eligible is only permission to claim; provisional/missing/malformed/unreadable eligibility never authorizes staging selection; claimed without matching active means interrupted/unknown. For uncertain active publication, an authoritative unchanged prior pointer **plus a settled writer** proves precommit failure; an unreadable/uncertain result or still-running writer permits no candidate deletion, fallback or second selection. Retain ownership, perform bounded safe shutdown and report uncertainty rather than guessing. Independent valid active data is usable only when no unresolved writer can still supersede that selection.

Failed-generation rejection markers still protect locked/partial payloads and provide truthful failure disposition; the prior positive claim prevents failed rejection persistence from authorizing a blind same-UUID relaunch. Interrupted/failed-target suppression also survives fallback/cleanup: the automatic scheduler cannot evade it by creating a fresh UUID for the same target. A fresh explicit Install or a separately eligible newer build is required. Do not erase the claim/receipt until equivalent bounded suppression evidence is safely retained; failed persistence leaves the claim in place. Retire claimed/failed directories only after their actual child/worker has exited; never reclaim current active data.

Store only this current job's canonical install-command attribution with its pointer evidence; other accepted join associations are bounded in memory. A join response identifies its own token and canonical job while retained. After supersession/eviction/restart, matching job/build alone cannot prove that a missing caller token was admitted, and a surviving canonical receipt cannot be presented as that join's result. Exact generation identity can prove **current selection** independently of uncertain historical command attribution. No permanent join-token list, password/session material or full request history belongs in dataset files.

## Activation and process ownership prerequisites

The selected gate applies to pending, already-active and bundled initial startup. Before exact activation authorization, permit only declared internal initialization: dataset-independent repeatable schema/bootstrap/permission/key preparation and checked local indexes/resources. Defer business-row transitions, history/event publication, dataset-derived mutations, pruning, recurring collectors, provider reads, credential/OBS work, Markets resume and arbitrary extension imports/migrate/register hooks. An active-pointer rollback cannot undo arbitrary app Store writes; the allowed initialization invariant needs explicit review. Do not hold a database transaction across awaited startup or copy the whole profile to imitate rollback.

The child may bind listeners for internal readiness, but external mutation and effectful GET/callback paths reject as temporarily unavailable **before admission**, with no unbounded queue. Public output stays conservative and cannot obtain release authority. Pure safe inspection/static shell may report preparation status. Defer arbitrary trusted-extension dynamic import itself: top-level code can perform effects; a reviewed pure built-in import is a separate narrow contract, not a sandbox guarantee. Internal readiness must not await the dormant work it is gating, avoiding a parent/child deadlock. After commit, bound activation acknowledgment/convergence and separately report startup-effect failure.

Select a **child-lifetime runtime-occupancy fence** in addition to the launcher lease. A separate child-held lease retained until process exit is a concrete candidate mechanism; P1 must independently settle/prove its helper/platform handoff before lifecycle implementation. Under the launcher lease, a new supervisor must establish that occupancy is released **before selection, cleanup or Store access**. No unguarded handoff interval may allow another reader/writer generation; PID existence or acquiring today's parent-only lock is not proof. Normal replacement still requires actual exit. Abrupt parent death while the orphan drains, failed creation, forced exit and lock transfer are required automated schedules; native Windows behavior remains a separate limit.

Embedded/direct hosts retain a usable explicit path: the host validates/authorizes its immutable active generation and owns equivalent exclusive lifetime rules before starting effects, rather than waiting forever for nonexistent supervisor IPC. Without a managed activation owner, Install prepares eligible data and reports restart required; it cannot claim live activation. Normal already-active/bundled startup must not add install-style provider calls or full hashes/tree scans to passive reads. The exact host/child activation adapter is an implementation prerequisite, not an existing API guarantee.

## Cooldowns, cancellation and passive reconciliation

Separate **metadata cache freshness** from provider embargo/backoff and local failed-build suppression. A valid cached candidate may install without another metadata request while its cache TTL is live. A provider throttle floor cannot be bypassed by Install, Check, join/escalation, manual failed-build retry, restart or cached metadata. Apply the selected SDE provider scope to both latest-metadata and archive requests; until narrower authoritative scope is established, use the common SDE provider origin conservatively. Parse archive Retry-After as well as metadata responses; a retry lifetime/cap may end or defer work but must never shorten the provider's not-before floor. Local conversion/disk errors are not fabricated provider throttles. Preserve validators, no redirects, one schedule owner, automatic failed-build suppression and fresh manual retry intent.

Finite admission, metadata/archive/worker deadlines, backoff attempts, total job lifetime and cleanup backlog precede implementation in P0-04. If a provider floor exceeds an admitted operation's remaining lifetime, finish with explicit deferred/blocked disposition instead of retaining an unlimited observer/job or busy loop. Scheduled future work is owned current-policy work, not automatic browser resubmission of the old POST; it must retain any still-current frozen target semantics or create a separately identified automatic latest-eligible job. Persist only bounded applicable cooldown/selection evidence, with clock/restart tests; do not reset it through unrelated settings saves.

No user Cancel endpoint is introduced. Browser navigation/abort/disconnect releases that observer, not a shared accepted preparation or completed eligible handoff. Unrelated settings saves/reads do not own cancellation. Before final eligibility commit begins, owner shutdown aborts fetch/build, waits for actual filesystem/worker completion and retires only its own provisional artifacts. After entry, settle/read back the exact publication; no uncertain pointer write authorizes a second generation or destructive cleanup. Failed rejection/claim/cleanup must remain explicit at the owning handoff; do not turn it into clean cancellation or successful stopped acknowledgment. Already committed active selection is never rolled back because shutdown, status publication or housekeeping failed.

Extend passive GET `/api/datasets` with current candidate/selection identity, runtime/activation identity, canonical job/origin/target/phase, its safe canonical install receipt and bounded requested-token attribution where retained. Cache validated activation metadata at startup/handoff; reads must not fetch providers, rehash generations, scan directories, resume workers or emit readiness. Bind status/SSE sequence to runtime/job; progress from a departed worker cannot overwrite a newer job. A lost/malformed POST acknowledgment gets one initial bounded passive read; unresolved evidence stays unknown with deliberate later inspection. Existing SSE/reconnect observation may publish new authoritative evidence, but neither a generic error nor an absent/superseded receipt permits automatic POST replay. Browser restart reads current truth without persisting/replaying lost payloads.
