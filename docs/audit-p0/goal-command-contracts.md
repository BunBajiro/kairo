[`index.mjs`](../../server/index.mjs) owns HTTP validation and manual progress/notes; [`goals.mjs`](../../server/goals.mjs) owns type lookup, creation, availability and automatic accounting. All scoped HTTP commands use the private session/Origin/CSRF/body boundary. `checkedChar` allows 0 and requires a current Auth row for nonzero selectors. Prefix update/delete routes consume the third path segment; extra-segment/method behavior needs exact-route acceptance, not a new defect claim.

Absolute unmet progress may fall; automatic completion latches. Cumulative entry high-water marks preserve earned units after rolling windows and avoid duplicate credit; mining's first eligible sample seeds a baseline. Shared source preparation is per refresh, with changed-key narrowing and unchanged-write avoidance.

`refresh` commits ledger/progress/status in a savepoint, then publishes completion with dedupe `goal:<id>:completed`. Savepoint release is **not necessarily the outer transaction commit**. [`Core.publish`](../../server/core.mjs) writes an event then immediately emits bus/invalidation; async listeners belong to bus drain. Core currently saves a collected snapshot before `goals.refresh`; a refresh exception can reach the collector's broader failure path. Combat has retained canonical records and calls refresh on changed batches. These seams require the target guarantees below; source reading alone does not confirm a new defect.

Private note bodies are not Stream input. Auth disconnect deletes its connection/snapshots/private HTTP cache, retaining Goals/notes/history; active connection state and retained local ownership are therefore distinct.

## Selected intent, validation and bounded identity

Use immutable caller token, storage lineage, exact pilot/entity/action/base and atomic current receipts from the shared contract. Repeated current tokens conflict/read back; no automatic mutation retry. Never infer noncommit from a generic HTTP error, timeout, abort, missing row or equal value. An uncertain local commit remains unknown until authoritative inspection; confirmed rollback/precommit rejection has zero domain effects. Publication/read failure after a known commit cannot reverse that result.

| Action | Selected validation and owner |
| --- | --- |
| Create Goal | Required string title trimmed nonblank, at most 160 code units; required finite numeric positive target at most `1e15`. Omitted source means manual; supplied source must be an exact supported ID. Typed automatic sources require a positive safe type ID below `2147483647`; other sources reject irrelevant type fields. Skill requires verified category 16 and integer target 1–5; asset/mining/industry/combat targets are whole safe units. Fractional valid manual/wallet values remain supported. Verify type/group identity from complete validated public/cache evidence before commit; do not trust a browser category/name as authorization. |
| Manual progress | Exact owned live manual Goal plus expected user-command revision; required finite numeric progress, preserving the existing clamp to `[0,target]`. Numeric strings/ambiguous objects are not valid numbers. Reopen remains explicit progress 0. Automatic goals reject manual changes. |
| Create private note | Required string body, trim as today, nonblank and at most 5,000 code units. Reject oversize text rather than silently truncate; preserve Unicode. No type lookup/provider work. |
| Delete Goal/note | Exact route, explicit captured pilot including 0, exact entity ID and live user-command revision. Already-absent explicit deletion requires a current authoritative collection base, separate from claiming an older delete succeeded. No broad prefix aliases, supplied foreign owner or mixed action fields. |
| Type lookup | One coherent name-or-ID selector, bounded exact nonblank name or valid numeric ID, strict complete provider type/group result. Public read/enrichment only; no live EVE credential is required. Valid shared names may be cached even after a view retires, but an obsolete result cannot select a type in another draft or become a Goal commit. ESI cache, cooldown and validation rules still apply. |

Validate full source-specific input before public lookup or mutation. Reject wrong types, missing/unknown intent fields and oversize values; do not introduce new limits below supported valid behavior without measured P0-04 justification. The byte/count/deadline budgets remain prerequisites. The historical lifecycle fixture uses manual+typeId only to force an await; strict source validation may replace it with an equivalent valid typed automatic fixture while preserving the proven accepted-work drain invariant.

New creates for pilot 0 support manual Goals/notes only. New nonzero-owner creates capture the current pilot identity/connection incarnation after body validation; a healthy access token, enabled source or ready sample is **not** required for manual/notes or for creating a waiting automatic Goal. Recheck that captured owner before commit; deletion/replacement of the connection conflicts rather than silently retargets. Ordinary token rotation keeps the identity. Existing retained local Goals/notes remain privately inspectable/deletable, and manual progress remains locally editable, under their exact stored pilot/row ownership without requiring live EVE access. This does not authorize automatic collection for a disconnected pilot or add a new historical-pilot picker. Passive reconciliation must work for its captured retained owner after disconnect.

Select separate Goal and Note membership entities per pilot. Each carries a nonreused monotonic membership revision and one latest create/delete receipt. Each live row carries its user-command revision/latest receipt; automatic Goal accounting has a separate progress/status version. New opaque IDs derive from a bounded canonical tuple of lineage, collection, pilot, caller-observed membership base and fresh nonce, as in Imports. The ID is identity, not authority. Create requires that exact ID absent and membership base current at admission and commit; it must never UPSERT another row. Concurrent creates from the same base conservatively conflict, while existing independent Goals/notes do not conflict merely because another member changed. No hidden rebase or automatic create retry.

Creation atomically inserts row/tracking, required creation accounting/event, user revision/receipt and advances membership/receipt. Manual changes advance only that Goal's command revision; automatic progress cannot erase the last user receipt or starve a delete by constantly changing its CAS base. Delete atomically removes row/dependent tracking/credits and advances membership/receipt. Already-absent deletion advances membership using its authoritative absent base; absence alone cannot attribute a prior command. A delayed old create/update cannot resurrect a deleted ID. Retain no permanent deleted-ID or per-click history. Aggregate retained owners/rows/receipt bytes require P0-04 capacity policy; count limits must reject before acceptance rather than silently discard current data/intent.

Receipts contain only identity/action/base/result revisions, safe boundaries and necessary numeric result metadata. Do not duplicate note bodies, arbitrary titles or private payload digests in receipts/diagnostics. Private content stays in its domain row; the tuple attributes the immutable submitted command without retaining another copy. A surviving membership create receipt can prove creation/ID after subsequent progress changed the row, but current progress must be labeled current, not the original create result. Superseded/evicted evidence may leave old acknowledgment unknown.

Required initial accounting concerns only the newly created Goal. The existing whole-pilot refresh may update other Goals as a separately owned follow-up; its failure is not creation failure. Preserve one shared source preparation per affected pilot/source, narrowed changed-key work and durably admitted evidence under the following retention rule. Receiving a provider response or populating an eligible ESI cache is distinct from committing/publishing a Core source snapshot. Do not add one full source scan per Goal or use command revisions as source freshness. Full cumulative arithmetic, clock/cutoff correctness and source-window coverage still require their later owner regressions.

**Bounded unresolved source evidence is an implementation prerequisite.** Reserve at most one finite pending-observation slot per affected source owner before accounting; retain immutable validated sample/provenance, captured connection/source identity and the dependent Goal cohort/basis needed for that observation. Capture its stable observation/event time and Session ownership (including explicit no-Session) so delayed accounting/restart cannot move completion into a later Session. The cohort identifies original definitions: deleted/retired members settle as such without recreation or endless waiting, and newly created Goals do not inherit the old observation's attribution. Durably stage that evidence before claiming it admitted for accounting. A later sample cannot overwrite or supersede the unresolved slot. The snapshot/accounting/event transaction atomically consumes it on success. Confirmed rollback keeps the staged evidence for bounded local retry with the original identity; uncertain commit first reconciles the staged/committed identity, never blindly reapplies credit. Mutable latest ESI cache alone is not durable retention proof. Attempts/deadline/capacity exhaustion stops further affected-source admission and reports unavailable/accounting-blocked while retaining the unresolved slot for deliberate bounded recovery; it does not wait/retry forever or invent completed coverage. Independent sources remain eligible. Startup inspects the retained slot before admitting its successor; owner replacement or lost eligibility cannot retarget its private evidence to a new connection. Explicit retirement preserves an honest unresolved/gap disposition rather than silently counting or discarding it. A failed/uncertain staging write cannot claim durable admission: retain the current owned response while bounded storage reconciliation is possible, stop supersession, and report failed handoff if durability cannot be established. Process loss before durable staging is an explicit coverage limit, not a recoverable accepted observation. This is one bounded current slot per source, not a raw-event backlog or per-Goal snapshot journal; exact bytes, cohort size, retry/deadline, retention and recovery eligibility require P0-04 and owning P1/P2 proof before implementation.

Already staged accounting retains its captured authority through module disable or observer retirement; retry age is not fresh source admission. Later eligibility loss blocks new provider/current-source publication or retargeting, not earned accounting. If Auth retirement requires discarding private pending material, first settle its admitted semantics under that captured owner or retain an explicit unresolved failure; do not silently drop accepted credit.

## Admission, drain and passive reconciliation

After complete body/schema validation and current runtime activation/owner/base checks, reserve finite create preparation **before** type lookup. Capture immutable payload, identity, dataset/runtime dependencies and original deadline. Closing admission rejects new/unaccepted work; it does not retroactively reject a valid accepted create solely because lookup is pending or its HTTP socket closed. Keep dependencies alive through validation/final local transaction and downstream drain. Actual owner/base retirement or exhausted budget can reject still-uncommitted work honestly. No database transaction spans an await. The existing lifecycle proof covers transport disconnect, not Auth disconnect; the latter needs new explicit acceptance.

Type lookup and accepted create continuations have finite aggregate capacity/bytes/waiters/deadlines. Shared compatible public metadata reads may remain useful to other owners; leaving a view is not rollback or a reason to cancel another consumer. No retry loop, provider cooldown bypass or unlimited pending progress chain. A bounded drain failure remains failed handoff, with actual dependencies retained until settled; an abort request or fulfilled UI refresh waiter does not prove work completed.

Select passive forms on existing private reads: **GET `/api/goals?character=<pilot>&inspect=command`** and **GET `/api/notes?character=<pilot>&inspect=command`**, with either exact `id` or the caller-known immutable creation tuple. Return only live/absent identity, row command revision/latest receipt, collection revision/latest receipt and current status tagged separately; private current content is requested explicitly and remains bounded. Ordinary list/bootstrap responses expose the bases needed for controls. These new inspection selectors validate exact shape and do not call `refresh`, type lookup, source projection, full timeline, full Goal list or providers. They remain available for exact retained local owners after disconnect. Wrong lineage/tuple, superseded receipt, read failure or absent row is unavailable evidence, not noncommit.

Use one initial targeted read after unknown acknowledgment, with deliberate later inspection if unresolved. Durable current evidence survives normal runtime restart; reset changes lineage. Browser loss need not persist private pending payloads; reopen reads current state and surviving evidence without replay. Read-before-delayed-commit cannot declare rejection. No success claim merely from a similar title/body/progress or a timeline event. Current source availability is separate from local command attribution.
