## Selected intent, identity and validation

Use exact `/api/places/{system|constellation|region}/{canonical-positive-decimal-id}` routes, with one complete segment per identity and no trailing/extra/encoded path aliases or permissive numeric spellings. ID must be a positive safe integer. GET, PUT and DELETE are the only scalar methods; reject unsupported methods without parsing/mutating a note. Validate supported list/inspection selectors exactly; reject a supplied pilot selector rather than imply a pilot-scoped annotation owner. Shared private guards/body limits still apply, including to DELETE's new command precondition envelope. No alternate mutation path may bypass the same domain owner.

PUT represents the complete note intent: required string body, array of string tags and exact status; name is an optional bounded display label, never identity/authorization. Omitted name uses a deterministic local label/ID, with the returned value explicit. Preserve empty body, blank note plus marker/tags, and explicit empty-note saves as valid rows; they are not DELETE. Preserve body whitespace/Unicode. Name trim and tag trim/empty removal/stable deduplication are deliberate canonicalization, reflected in the returned result; reject overlong normalized names/tags, body over 12,000 code units, more than 12 normalized tags, wrong types, unknown fields/status or silent-loss cases. Retain the existing 100-name/32-tag limits; do not truncate submitted text or drop excess tags. Raw input/aggregate bytes and normalized values need separate finite P0-04 limits; duplicate/empty tags do not justify unlimited normalization work. Normal browser comma-separated tags remain supported. The complete body is validated before any command write.

**New identities require positive local K-Space classification.** At an absent-row creation, bind an authoritative ready static-catalog generation and exact entity classification; unknown/unavailable evidence does not mean known space. Systems must be known-space members; constellation/region classification must be coherent from complete local catalog membership, with no wormhole descendant or mixed/ambiguous classification. Do not ask ESI to resolve an unknown identity. Recheck the captured generation/eligibility and command base at the atomic commit boundary; a replaced basis conflicts rather than silently changing the submitted target. Build a reusable generation-owned identity index; do not add a full static-system scan per note operation. Numerical construction/memory costs remain P0-04 work.

Persist the acceptance provenance needed for an existing note's identity. Temporary catalog absence/unavailability alone does not prevent bounded local read/edit/delete of that same live incarnation. A positively superseding conflicting/J-Space classification blocks new edits/publication into Atlas, but does not delete or move the note: exact private inspection and explicit deletion remain available. Current map-local J-Space notes are never read or modified by this API. No historical-profile migration, new orphan-note picker or repair workflow is implied; this protects valid current-build local data during dataset changes. A clean absent GET does not write a placeholder or establish acceptance merely by returning empty form fields.

Select **three fixed membership entities, one per kind**, plus a command revision/latest receipt on each live note. A missing-note read returns explicit absence and that kind's membership base. Creating an absent key requires it still absent and its observed membership base current; deleting an absent key likewise requires the current absent base. Both advance membership atomically and retain its latest receipt identifying the exact key/action. Concurrent absent creates/deletes of the same kind conservatively conflict; no hidden merge/rebase or indefinite absence history is required.

Existing note updates/deletes CAS the exact live incarnation/revision, independent of unrelated note edits or membership changes. Create gives a nonreused birth revision/identity, bound to storage lineage and the successful membership transition; later recreation of the same `(kind,id)` cannot match an old live-row base. Existing update advances only that row's revision, including a same-value commit. Live delete atomically removes the row and advances kind membership/receipt. An old update cannot turn into an UPSERT after deletion; an old absent create cannot cross a create/delete cycle. No permanent tombstone or per-click journal. Row/receipt capacity cannot evict valid notes to make room silently; P0-04 settles finite admission/retention bounds before implementation.

Each fresh command token binds immutable validated intent, exact key/action, storage lineage and live-row or absent-membership base. Follow the shared current-token reuse/conflict rule and exact bound receipt tuple; bare token equality, a matching note, timestamp or absent row is not attribution. Retain only current row and latest per-kind membership receipt metadata, without copying note text/name/tags or their private digests into receipts. A later member change can supersede deletion/create attribution; report unavailable evidence honestly. Reset changes lineage; normal restart preserves revisions/receipts. Independent kinds and existing rows remain independently writable.

## Commit, read-back and delivery

After full body/schema validation, current runtime admission and authoritative key/base/eligibility checks, reserve bounded local command capacity. No provider preparation or asynchronous transaction is needed. A short transaction groups note insert/update/delete, revisions/provenance and the necessary receipt/membership write. Failed required writes roll back together. Recheck bases inside that transaction before writes; a concurrent database connection cannot slip a replacement through a pre-transaction check. Return the exact committed note/revision or deletion/absence receipt, never a later mutable reread. Generic storage failure can leave commit uncertain; only attributable confirmed rollback proves noncommit.

No semantic timeline/Session event is required for a private Places edit. After the actual outer commit, publish a bounded, content-free installation-wide key/revision invalidation through the existing private delivery owner. A successful edit in one pilot view must converge in another view of the same key without treating it as a different pilot's data. Invalidation and derived Atlas refresh are separate outcomes; failure cannot undo the known commit or authorize repeating PUT/DELETE. Reconnect/open can recover current projections with targeted reads. No note content in semantic events, diagnostics, toasts or public Stream; existing private export remains intentional. Do not repair views by replaying success toasts, provider calls or broad history/state polls.

Extend the **existing scalar GET** with `?inspect=command` as a passive metadata-only command-inspection form. It returns live/absent identity, lineage, current live revision/latest receipt when present, kind membership revision/latest receipt, without note content. Normal editor GET returns bounded current note content plus the bases needed to save; an absent editor response distinguishes authoritative absence from its empty form defaults. Label current content separately when only an older create/delete receipt survives. Read note/absence, row receipt and kind membership metadata from one coherent short read snapshot, including against other database connections. The reader uses exact key/metadata reads, not `Universe.detail`, the full list, a metadata provider or a write. A syntactically valid missing key can report authoritative storage absence even if its catalog identity is unknown or J-Space; separately report creation eligibility, and never treat absence as permission to create. Inspection remains usable for a captured accepted note during catalog/connection changes; malformed stored content is unreadable, not fabricated absence. Metadata inspection should not require successfully rendering arbitrary note content.

Use one initial authoritative inspection after lost/malformed/mismatched acknowledgment, then deliberate bounded later inspection if unresolved. A read before the admitted command commits cannot prove rejection; a missing/superseded receipt cannot either. No automatic PUT/DELETE replay. Browser loss may lose in-memory pending payloads; reopen reads current state without pretending that lost intent was rejected. Current command evidence survives ordinary runtime restart, with no compatibility obligation across a new profile.

List HTTP-058 uses bounded cursor pages ordered by `updated DESC, kind, entity_id`. Maintain one separate installation-wide list generation, advanced atomically by every successful Places command (including same-value/absent-delete), to detect updates that reorder or change page content. This read version is not a command CAS base and does not make independent live writes or absent bases stale. Bind the cursor to storage lineage, that generation and exact last sort tuple; normal restart preserves them, while reset invalidates the old lineage. Read each page/its metadata coherently, and return an explicit discontinuity if lineage or generation changed. No hidden pagination restart/retry loop or full-list snapshot/history is required. The list is not the receipt lookup. Aggregate note storage, list/Atlas input size and private export bounds are separate budgets; a per-body cap is not an aggregate limit. Preserve the existing separation between private annotations and unrelated route preparation; a note receipt/read must not add lifetime history, provider requests or per-note background loops.

Closing runtime admission rejects new/unaccepted commands; a valid accepted local command retains dependencies through its final transaction/result even after HTTP disconnect. Actual base/eligibility retirement or deadline exhaustion can reject uncommitted work, but a view change or closing socket is not rollback. Drain owns the actual work, with finite capacity/bytes/deadlines and no hidden successor promise chain. No new provider retry/cooldown policy is needed for local notes.

## Editor ownership and proof still owed

Capture exact key, editor instance, draft generation, command base and submitted snapshot for Save; increment draft generation for all edits, including A→B→A. Pilot changes alter view ownership only. Dirty place capture cannot be retargeted by new system props or `allowedScopes`. Initial, refresh, Discard and acknowledgment callbacks must verify their own editor/key/request generation before changing draft, loading/busy/error state or publishing feedback. Do not let an obsolete finally unlock another operation. The editor also honors explicit creation/edit eligibility; empty form defaults for an unknown or J-Space key cannot enable a new global note. Keep busy fieldset/tab protection throughout Discard and Save as today; a failed discard retains the draft and permits recovery. There is no new Delete UI requirement.

Mounted busy protection plus authoritative CAS is sufficient; this slice does not require a new serialization queue. Bound aggregate pending command snapshots/tokens across remounts, using the installation key rather than the selected pilot. If a dependent successor is explicitly accepted, it may adopt a proven predecessor revision only under the shared continuation rule; unknown/conflict pauses that dependent work without dropping drafts or rebasing onto another tab. A clean current editor may adopt an authoritative newer note; a dirty editor keeps its text/base and must resolve a stale-base save explicitly. Discard reads current saved state and replaces only its owned unsubmitted draft; it neither cancels an already accepted save nor proves its unknown outcome. Known commit plus failed refresh remains a committed save with a separate read error.
